## 摘要
蒙特卡洛树搜索（MCTS）使人工智能（AI）能够进行决策，但在传统处理器上需消耗55-300瓦的功率，限制了其边缘部署。内存计算（IMC）在常规工作负载下能效高，但被认为不适用于不规则的多阶段算法。我们引入了阶段到原语的分解方法，将每个算法阶段重新表述为硬件原生的IMC原语。应用于MCTS时，选择、扩展、回滚和反向传播分别映射到内容可寻址存储器、组合逻辑、阻变随机存取存储器（RRAM）交叉阵列和静态随机存取存储器，从而使搜索保持在芯片内。采用22纳米工艺及实测RRAM阵列参数，IMC-MCTS在执行9x9围棋时功耗约为60毫瓦，能效比中央处理器（CPU）高96倍，比H100图形处理器（GPU）高65至2059倍。其达到的欧洲围棋联合会等级分在开源围棋引擎（Pachi-UCT和Michi-C）的样本量不确定范围内。同一硬件平台可在四个AI领域运行八种应用。

## Abstract
Monte Carlo tree search (MCTS) enables artificial intelligence (AI) decision-making, but requires 55-300 W on conventional processors, limiting edge deployment. In-memory computing (IMC) is energy-efficient on regular workloads but has been considered incompatible with irregular multi-phase algorithms. We introduce phase-to-primitive decomposition, which reformulates each algorithmic phase as a hardware-native IMC primitive. Applied to MCTS, selection, expansion, rollout and backpropagation map to content-addressable memory, combinational logic, a resistive random-access memory (RRAM) crossbar and static random-access memory, keeping search on chip. At 22 nm with fabricated RRAM-array parameters, IMC-MCTS consumes ~60 mW for 9x9 Go, achieving 96x energy efficiency over a central processing unit (CPU) and 65x-2,059x over an H100 graphics processing unit (GPU). It reaches a European Go Federation rating within sample-size uncertainty of open-source Go engines (Pachi-UCT and Michi-C). The same substrate runs eight applications across four AI domains.

- **核心贡献**：论文提出“阶段-原语分解”（Phase-to-Primitive Decomposition）方法论，将MCTS的四个阶段分别映射到四种硬件原生IMC原语，首次实现MCTS的全片上、多原语内存计算，显著降低功耗至毫瓦级。

## 2. 提出的方法论

### 2.1 核心思想
- **阶段-原语分解**：将异构算法视为一系列计算阶段，每个阶段独立映射到最适合其计算模式的IMC原语。步骤：**剖析（Profile）→ 匹配（Match）→ 重构（Reformulate）→ 组合（Compose）**。
- **MCTS四阶段映射**：
  - **选择（Selection）** → 内容可寻址存储器（CAM）：并行关联查找，将O(n)指针追逐降为O(1)单周期。
  - **扩展（Expansion）** → 组合逻辑（Game Logic Unit）：单周期并行生成所有合法走法。
  - **回滚（Rollout）** → RRAM交叉阵列（Crossbar）：模拟矩阵向量乘法，执行固定延迟的两层神经网络评估。
  - **反向传播（Backpropagation）** → SRAM：原位读写更新树统计数据，消除片外数据传输。

### 2.2 关键技术细节
- **三个关键重构**：
  1. 变长随机回滚 → 固定延迟两帧神经网络（如9×9围棋162→96→3）。
  2. 指针追逐树遍历 → 并行CAM查找，节点状态存储为CAM比特模式。
  3. 片外统计更新 → 片内SRAM读写（含饱和计数器）。
- **架构**：分层缓冲芯片（tiled chip），每个核心（core）实现完整四阶段流水线，由TCAM有限状态机控制。
- **硬件参数**：22 nm工艺；RRAM crossbar采用差分电导权重（0.1–99.9 μS），1-bit DAC输入，8-bit ADC输出；读延迟768 ns（256 ns字线充电+512 ns ADC转换）。
- **算法**：选择策略为UCB1（也支持PUCT扩展），但实验中使用UCB1以保证可比性。

## 6. 主要结论与发现

- **能效**：IMC-MCTS在9×9围棋上功耗约60 mW，能效比CPU高96倍，比H100 GPU高65–2059倍（取决于批次大小，公平比较为批次256时的65倍）。
- **决策质量**：达到约1727 EGF（3级），与开源引擎Pachi-UCT和Michi-C在样本量不确定度内相当；优于IMC-weak（1139 EGF）和GnuGo-L10（1500 EGF），远低于KataGo（~3200 EGF）。
- **通用性**：同一硬件（仅重编程交叉杆权重）可运行8种网格决策任务，所有任务SGG > +0.05。
- **阶段-原语分解有效性**：证明IMC并非只能用于规则工作负载，通过分解可加速不规则多阶段算法。

## 7. 优点

- **方法创新**：首次提出阶段-原语分解，为其他不规则AI算法（约束求解、部分可观察规划）开辟路径。
- **全片上搜索**：所有阶段的数据在片内流通，无片外数据传输，实现极致能效。
- **硬件协同设计**：CAM的O(1)遍历防止交叉杆空闲；交叉杆的确定性时序使流水线固定深度；各原语互依赖形成整体优势。
- **实测参数建模**：RRAM交叉杆参数来自实测180 nm 64×64阵列，经缩放至22 nm；ADC/DAC延迟基于真实芯片。
- **噪声鲁棒性验证**：在高达10%电导噪声下决策质量仍稳定，证明MCTS的统计平均天然容忍模拟非理想性。
- **公平能效对比**：区分算法增益和硬件增益（图3c）；对比批次256的GPU（公平吞吐量工作点），且给出等工艺（22 nm→4 nm）投影预估约100–180×优势。
- **开源思路**：预计发布所有代码和模型，便于复现。

## 8. 不足与局限

- **状态空间局限**：仅适用于可表示为网格的状态（围棋、棋盘游戏、网格导航）；非网格状态（连续机器人控制、大图路由）需编码改造。
- **未进行全芯片流片验证**：所有能量和延迟基于22 nm逻辑综合、SRAM建模和RRAM实测参数，但CAM-交叉杆互动在全流水线速率下的硅验证是必要下一步。
- **训练数据量小**：围棋评估器仅用2000个位置（9×9），限制绝对棋力；论文强调这不是优化目标，但真实部署需更大数据集才能达到更强水平（如职业段位）。
- **跨域实验统计力度弱**：每任务仅10局，+0.05的SGG阈值只是指示性，部分较低SGG（如Go +0.09）在10局中可能受噪声影响，需更大样本确认。
- **CAM容量限制**：树大小需匹配CAM容量，对于超大棋盘（19×19）可能需层次化设计，文中未深入探讨。
- **PUCT扩展未实验**：虽然硬件支持PUCT，但所有实验使用UCB1，PUCT的实际性能未验证。
- **系统级假设**：假设芯片集成PCIe接口，但未讨论与其他边缘SoC的集成开销；60 mW为芯片功率，未包含外部供电转换损耗。
- **其他AI算法推广**：阶段-原语分解的通用性仅通过MCTS初步验证，对其他不规则算法（如约束满足、神经符号推理）需要额外案例验证。
