## 摘要
存内计算通过将计算与存储共置来应对内存墙，但由于真实的PIM硬件仍然稀缺，模拟成为探索PIM设计空间的主要手段。然而，现有的PIM模拟器各自只覆盖了该空间的一部分：它们通常建模单一存储技术、将处理单元固定在存储层次结构的某一层级、支持单一执行模型，并且止步于设备边界。因此，我们提出了PIMID，一种执行驱动和轨迹驱动的全系统模拟器，在一个工具中弥补了这些空白。PIMID支持共享内存和消息传递两种执行模型，能够在十一种存储技术（七种DRAM标准、SRAM和三种非易失性存储器）上并行运行带注释的OpenMP和MPI并行代码；它可以将处理单元放置在任何位置，从子阵列到逻辑芯片，扫描处理单元数量和核心模型保真度，并根据实测拥塞为每种技术计算内存网络价格。其单进程主-从设备协同模拟能够解析端到端的时间和能量分解（主机准备、设备计算和显式边界开销），这是纯设备工具无法生成的。在由此产生的双执行模型数据集上，PIMID表明：仅存储技术就能使执行时间变化超过一个数量级，且最佳主机主存并非最佳PIM基底；规则内核随处理单元数量超线性扩展，因为内存带宽与计算协同扩展；在消息传递下的图遍历会遇到共享内存下不存在的集体通信瓶颈；在全系统范围内，卸载仅在带宽类内存上以时间换取能量：共享内存卸载在HBM3上节省能量，而16核主机则能保持所有端到端时间优势。PIMID的插件接口允许随着PIM技术的发展，通过标准化的YAML规范添加新的引擎和模型。

## Abstract
Processing-in-Memory addresses the memory wall by co-locating computation with memory, but because real PIM hardware remains scarce, simulation is the primary way to explore the PIM design space. Yet existing PIM simulators each cover only part of that space: they typically model a single memory technology, fix processing elements at one level of the memory hierarchy, support a single execution model, and stop at the device boundary. We therefore present PIMID, an execution- and trace-driven full-system simulator that closes these gaps in one tool. PIMID supports both the shared-memory and message-passing execution models, running annotated parallel code in OpenMP and MPI side by side across eleven memory technologies (seven DRAM standards, SRAM, and three non-volatile memories); it places PEs anywhere from subarrays to logic dies, sweeps PE count and core-model fidelity, and prices the in-memory network per technology from measured congestion. Its single-process host-device co-simulation resolves an end-to-end time and energy breakdown (host preparation, device compute, and explicit boundary charges) that device-only tools cannot produce. Across the resulting dual-execution-model dataset, PIMID shows that the memory technology alone moves execution time by more than an order of magnitude and that the best host main memory is not the best PIM substrate; that regular kernels scale superlinearly with PE count as in-memory bandwidth co-scales with compute; that graph traversal under message-passing hits a collective-communication wall absent under shared memory; and that at full-system scope the offload trades time for energy only on the bandwidth-class memory: shared-memory offload saves energy on HBM3 while a 16-core host keeps every end-to-end time win. PIMID's plugin interfaces let new engines and models be added through standardized YAML specifications as PIM technology evolves.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：存内计算（PIM）通过将计算单元移至内存附近来缓解“内存墙”问题，但真实PIM硬件稀缺，主要依靠模拟器进行设计空间探索。然而，现有PIM模拟器存在四大缺陷：
  - 仅支持单一内存技术（如仅DRAM或仅NVM）；
  - 将处理单元（PE）固定在内存层次结构的某一层级（如仅逻辑芯片级）；
  - 只支持单一执行模型（共享内存或消息传递之一）；

- **整体含义**：现有工具限制了研究者全面探索PIM架构的能力。PIMID旨在填补这一空白，提供一个统一、可扩展、覆盖多维度设计空间的全系统模拟器。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：构建一个执行驱动与轨迹驱动相结合的全系统模拟器，将主机模拟引擎（基于QEMU+ZSim）与设备模拟引擎（支持可配置PE）在单进程内通过事件队列协同，同时集成多种内存时序/能量模型和网络模型。
- **关键技术细节**：
  - **多内存技术支持**：集成Ramulator 2.0（7种DRAM标准）、CACTI（SRAM）、NVSim（3种NVM：STT-MRAM、PCM、ReRAM），共11种内存技术。
  - **细粒度PE放置**：PE可从子阵列、bank、bank group、channel、rank到logic die任意层级放置。
  - **双执行模型**：同时支持OpenMP（共享内存）和MPI（消息传递）并行代码，在相同设备模型上运行，网内通信基于GARNET仿真拥塞定价。
  - **主机-设备协同模拟**：单进程内两个独立时钟域，通过事件队列同步；边界开销（缓存刷新、启动、数据传输）显式建模，支持PCIe、CXL、NVLink等互连链路模型。
  - **功耗与能量建模**：集成McPAT（计算/插槽功耗）+各内存模型自带的能量输出；包含背景/刷新/读写/接口等精细能量项。
  - **网络建模**：GARNET提供周期精确的片上网；解析模型（跳数延迟、M/D/1排队）用于快速扫描。

- **公式或算法流程**：无显式公式；整体流程为：用户代码经QEMU用户态仿真执行，遇到标注的卸载区域时，线程切换至设备模拟引擎，设备内PE执行对应并行任务，通过共享事件队列同步，最终输出端到端时间与能量分解。

## 6. 主要结论与发现

- **内存技术影响显著**：仅改变内存技术，执行时间变化超过一个数量级（最高19.1×）；最佳主机主存（如HBM3）并非最佳PIM基底（DDR5在bank级PIM中反而更快）。
- **规则内核超线性扩展**：STREAM、stencil等在64 PE下获得167×~172×加速，因为PE增加同步增加了内带宽。
- **图遍历的集体通信墙**：BFS在消息传递模式下，PE数从16增至64时执行时间从2460万周期猛增至24.2亿周期（~100×），而共享内存下仅稍微饱和。此现象源于PIM内多点同步的成本。
- **全系统能量权衡**：共享内存卸载仅在HBM3上节能（最高1.6×）；DDR5卸载仅达持平；消息传递卸载因额外通信开销从未节能。
- **主机基线对比**：16核主机总能保持时间优势；PIM卸载弱PE（0.9W）能在非满载主机下比单核省能2~5倍。
- **PE核心模型影响**：从ALU到OOO核心，执行时间差距2.7×~17.5×，能量随wall-time降低。

## 7. 优点

- **全面性**：唯一同时覆盖11种内存技术、细粒度PE放置、双执行模型、全系统协同的PIM模拟器。
- **方法论可靠**：单进程协同模拟保证了主机与设备模型一致性（验证误差<0.1%）；设备侧结果与独立设备模拟一致。
- **实用性**：基于成熟组件（QEMU/ZSim/Ramulator2/GARNET/McPAT）构建，插件接口便于扩展；源码和容器镜像公开。
- **发现深刻**：揭示了此前工具无法观察到的现象（如集体通信墙、最佳主机与最佳PIM基底的倒置）。
- **实验设计系统**：四轴扫描+共同因素分析，支持广泛探索。

## 8. 不足与局限

- **模型抽象限制**：片内数据通信仅建模为带宽受限的DQ数据路径复用，未模拟器件内部精确的TSV阵列、全局/本地数据线层次等细节，不适用于签核级精确性需求。
- **能量耦合问题**：PE数量/放置变化时，功耗随配置变化，导致能量与时间解释时将二者分离；文中只在部分实验中直接解读能量。
- **未覆盖分布式PIM**：协同模拟当前仅支持单个设备，多主机/多设备尚未实现。
- **无硬件校核**：所有结果来自仿真，缺乏FPGA或真实芯片的交叉验证（作者声明为未来工作）。
- **可重复性细节**：部分实验为单次运行（除BFS消息传递外），虽然变异性已量化（≤3.6%），但未完全公开重复性统计。
- **工作量差异**：新兴内存扫描因容量限制，工作集较小，绝对数值不可与DRAM扫描直接比较。
