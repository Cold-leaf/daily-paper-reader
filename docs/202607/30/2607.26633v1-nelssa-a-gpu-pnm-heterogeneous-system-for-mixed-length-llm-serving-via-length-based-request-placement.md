## 摘要
现代LLM及其代理应用正在拓宽服务工作负载的范围，涵盖从几百个令牌到数十万个令牌的上下文长度。由于这些请求经常在同一服务窗口内交错出现，LLM服务系统必须处理高度异构的混合长度工作负载。这种混合长度工作负载暴露了以GPU为中心的服务架构的根本低效性，其吞吐量依赖于大型、内存受限的批次。在本文中，我们提出了NELSSA，一种将GPU与实际的处理近内存（PNM）加速器设备集成的LLM服务系统，以高效支持混合长度工作负载。NELSSA采用基于长度的请求放置，将短上下文请求路由到GPU，长上下文请求路由到PNM层，并结合运行时迁移以适应动态上下文增长而无需重新计算。我们将NELSSA原型化为一个端到端系统，在PNM上实现设备级稀疏注意力、GPU解码内核，以及主机端运行时，该运行时通过支持RPC和RDMA的CXL基础设施协调调度和跨层内存移动。在混合长度LLM工作负载中，与纯GPU基线相比，NELSSA将解码吞吐量（令牌/秒）提高了最多5.5倍，并将P99延迟降低了最多15倍。我们的端到端原型和实验结果表明，通过基于CXL的解聚实现的集成GPU-PNM服务，是一种有前途的系统范式，用于支持不断变化的工作负载的可扩展和灵活的LLM基础设施。

## Abstract
Modern LLMs and their agentic applications are broadening the range of serving workloads, spanning context lengths from a few hundred tokens to hundreds of thousands. As these requests frequently interleave within the same serving window, LLM serving systems must handle highly heterogeneous mixed-length workloads. Such mixed-length workloads expose fundamental inefficiencies in GPU-centric serving architectures, whose throughput depends on large, memory-constrained batches. In this paper, we present NELSSA, an LLM serving system that integrates GPUs with real-world Processing-near-Memory (PNM) accelerator devices to efficiently support mixed-length workloads. NELSSA employs length-based request placement to route short-context requests to GPUs and long-context requests to the PNM tier, incorporating runtime migration to accommodate dynamic context growth without recomputation. We prototype NELSSA as an end-to-end system, implementing device-level sparse attention on PNM, GPU decode kernels, and a host-side runtime that orchestrates scheduling and cross-tier memory movement over a CXL-enabled infrastructure with RPC and RDMA support. Across mixed-length LLM workloads, NELSSA improves decode throughput by up to 5.5x in tokens/sec and reduces P99 latency by up to 15x compared to GPU-only baselines. Our end-to-end prototype and experimental results suggest that integrated GPU-PNM serving, enabled by CXL-based disaggregation, is a promising system paradigm for scalable and flexible LLM infrastructures that support evolving workloads.

### **论文分析总结：NELSSA：一种通过基于长度的请求放置实现混合长度LLM服务的GPU-PNM异构系统**

#### **1. 核心问题与整体含义（研究动机和背景）**

*   **核心问题**：现代大型语言模型（LLM）服务面临**混合长度请求（Mixed-Length Workloads）** 的严峻挑战。真实世界的工作负载中，短请求（几百令牌）和长请求（超过10万令牌）频繁交织，导致以GPU为中心的传统服务架构出现严重效率问题。
    *   **GPU内存瓶颈**：长上下文请求的KV缓存巨大，迅速耗尽GPU有限的HBM容量，导致**有效批次大小（Effective Batch Size）** 崩溃，大幅降低系统吞吐量。
    *   **队头阻塞（Head-of-Line Blocking）**：长请求的执行时间远长于短请求，当它们被调度到同一批次时，会阻塞后续的短请求，导致**尾延迟（Tail Latency）** 急剧升高。
    *   **动态上下文增长**：在推理代理任务或思维链时，请求的上下文长度在生成过程中可能不可预测地增长，静态的放置决策失效，可能导致GPU内存耗尽和昂贵的重新计算开销。
*   **整体含义**：现有的GPU-only方案、KV缓存压缩方案或CPU卸载方案均存在根本性不足（如精度损失、带宽瓶颈或互联开销）。本文提出，解决该问题的关键在于*执行放置（Execution Placement）*，即：将内存受限的长上下文注意力计算，从GPU卸载到更适合此类负载的**处理近内存（Processing-near-Memory, PNM）** 设备上，构建一个异构系统。

#### **2. 方法论：核心思想、关键技术细节**

*   **核心机制**：**基于长度的请求放置（Length-based Request Placement）**。系统根据请求的序列长度，智能地将其路由到最合适的计算层执行。
    *   **路由阈值推导**：通过分析GPU密集注意力和PNM稀疏注意力在不同序列长度下的延迟模型，推导出硬件的**交叉点（Crossover Point）** 作为路由阈值 \( T_{input} \)。低于阈值的短请求由GPU处理，高于阈值的长请求由PNM处理。
*   **关键技术细节**：
    *   **分岔混合路由（Split-Batch Hybrid Routing）**：
        *   QKV投影和MLP计算在所有请求间全局批处理于GPU上，仅注意力阶段分支。
        *   **短请求**：在GPU上执行FlashAttention。
        *   **长请求**：GPU处理局部注意力窗口（sink和最近的tokens）；同时，基于查询的聚类相似性搜索，将全局稀疏注意力任务异步卸载到PNM节点。GPU在等待结果时可立即处理其他短请求的MLP计算。
    *   **无缝后台迁移（Seamless Background Migration）**：
        *   **动态处理**：请求在GPU上执行时，其上下文可能动态增长。当达到 \( T_{input} \) 或内存紧张时，触发迁移。
        *   **过程**：后台流异步地将历史的KV缓存传输到PNM节点，此过程不中断GPU的令牌生成。
        *   **结果**：迁移后，请求的后续注意力完全在PNM上执行，GPU只保留轻量级的质心元信息用于后续路由。这避免了昂贵的重新计算或交换。
    *   **系统架构**：基于CXL分解的GPU-PNM异构系统，包含Prefill Node、Decode GPU Node和NELSSA Node（PNM节点）。通过RoCEv2 RDMA实现高性能通信，解耦控制路径和数据路径。
    *   **KV分区**：在多PNM部署中采用**按头划分（Head-wise Partitioning）**，确保负载均衡，避免簇级分区可能造成的负载热点。
