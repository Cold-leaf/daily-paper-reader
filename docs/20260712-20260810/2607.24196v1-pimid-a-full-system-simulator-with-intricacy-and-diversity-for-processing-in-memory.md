## 摘要
存内计算通过将计算与存储器共置来应对内存墙问题，但由于真实的PIM硬件仍然稀缺，模拟是探索PIM设计空间的主要方式。然而，现有的PIM模拟器各自只覆盖了该空间的一部分：它们通常模拟单一存储技术，将处理元件固定在内存层次结构的某一层级，支持单一执行模型，并在设备边界处停止。因此，我们提出了PIMID，一种执行驱动和迹线驱动的全系统模拟器，在一个工具中弥合了这些差距。PIMID支持共享内存和消息传递两种执行模型，在十一种存储技术（七种DRAM标准、SRAM和三种非易失性存储器）中并排运行OpenMP和MPI注释的并行代码；它将PE放置在从子阵列到逻辑晶圆的任何位置，扫描PE数量和核心模型保真度，并根据测量拥塞为每种技术的存内网络定价。其单进程主机-设备协同模拟解决了端到端的时间和能耗分解（主机准备、设备计算和显式边界开销），这是仅设备工具无法产生的。在由此产生的双执行模型数据集上，PIMID表明，仅存储技术就能使执行时间变化超过一个数量级，并且最佳主机主存储器并不是最佳的PIM基底；常规内核随PE数量超线性扩展，因为存内带宽与计算共同扩展；在消息传递下的图遍历会遇到共享内存下不存在的集体通信墙；在全系统范围内，卸载仅在带宽类存储器上以时间换取能量：共享内存卸载在HBM3上节省能量，而16核主机则保持了每一项端到端时间优势。PIMID的插件接口允许随着PIM技术的发展，通过标准化的YAML规范添加新引擎和模型。

## Abstract
Processing-in-Memory addresses the memory wall by co-locating computation with memory, but because real PIM hardware remains scarce, simulation is the primary way to explore the PIM design space. Yet existing PIM simulators each cover only part of that space: they typically model a single memory technology, fix processing elements at one level of the memory hierarchy, support a single execution model, and stop at the device boundary. We therefore present PIMID, an execution- and trace-driven full-system simulator that closes these gaps in one tool. PIMID supports both the shared-memory and message-passing execution models, running annotated parallel code in OpenMP and MPI side by side across eleven memory technologies (seven DRAM standards, SRAM, and three non-volatile memories); it places PEs anywhere from subarrays to logic dies, sweeps PE count and core-model fidelity, and prices the in-memory network per technology from measured congestion. Its single-process host-device co-simulation resolves an end-to-end time and energy breakdown (host preparation, device compute, and explicit boundary charges) that device-only tools cannot produce. Across the resulting dual-execution-model dataset, PIMID shows that the memory technology alone moves execution time by more than an order of magnitude and that the best host main memory is not the best PIM substrate; that regular kernels scale superlinearly with PE count as in-memory bandwidth co-scales with compute; that graph traversal under message-passing hits a collective-communication wall absent under shared memory; and that at full-system scope the offload trades time for energy only on the bandwidth-class memory: shared-memory offload saves energy on HBM3 while a 16-core host keeps every end-to-end time win. PIMID's plugin interfaces let new engines and models be added through standardized YAML specifications as PIM technology evolves.

## 2. 方法论：核心思想、关键技术细节

### 2.1 总体架构

- PIMID 采用“域”式架构：**主机模拟引擎**和**设备模拟引擎**作为两个独立的周期计时域，运行在同一模拟进程内，通过共享事件队列和同线程域切换机制协同，避免了进程间通信开销。
- 主机引擎基于 QEMU 用户模式仿真 + ZSim 微架构模型，负责常规指令执行、缓存层次、主存访问。
- 设备引擎模拟内存侧 PE 及其本地存储层次，支持 ALU、simple、in-order、out-of-order 和 null 五种核心模型；PE 可放置在 subarray、bank、bank group、channel、rank、logic die 等不同层级。
- 设备引擎与独立设备仿真模式使用同一设备模型，保证“平价不变量”（parity invariant）。

### 2.2 记忆体技术支持

- 集成 Ramulator 2.0（七种 DRAM：DDR3/4/5、LPDDR5、GDDR6、HBM2、HBM3）、CACTI（SRAM）、NVSim（STT-MRAM、PCM、ReRAM），共支持 11 种记忆体。
- 记忆体抽象层统一各模型接口；DRAM 访问时序依据各 JEDEC 标准组织，NVM/SRAM 使用各自模型。

### 2.3 主机-设备协同仿真

- 代码通过注释标记卸载区域：区域外由主机执行，区域内由设备执行。
- 边界穿越显式计费：PCIe Gen4/5、CXL 2.0/3.0、NVLink 级、2.5D interposer 等链路模型，含延迟、带宽、协议开销；同时计入记忆体模型自身的读写费用。
- 单进程双域架构使得设备侧周期与独立设备仿真结果一致（误差 <0.1%）。

### 2.4 网络与功率建模

- 网络：GARNET 提供周期级模拟；DRAM 按技术生成层级化 H-Tree 结构；SRAM/NVM 使用两级层次，可选择拓扑（实验中用 2D mesh）。另配有基于解析模型（跳数+队列争用+MLP）的快速扫描选项。
- 功率：McPAT 计算 PE、控制器、H-Tree（总线模式）；记忆体阵列能量来自各模型（Ramulator2 经 JEDEC IDD 校准；CACTI；NVSim）。包含背景功耗、刷新功耗、终止/ODT 功耗等；主从双方、设备侧、系统级功耗按组件粒度统一核算。
- 功率管理采用功率门控：完全空闲组件不贡献功耗。

### 2.5 编程模型支持

- 同时支持 OpenMP（共享内存）和 MPI（消息传递）两种执行模型。
- MPI 运行时基于共享内存邮箱实现，无需外部 MPI 安装。
- 共享内存使用实时滚动平均拥塞反馈；消息传递使用冻结时期的 GARNET 测量样本进行确定性计价。

### 2.6 可扩展性

- 所有配置通过 YAML 文件指定；插件接口允许通过标准化 YAML 规范添加新的模拟引擎和模型，无需修改核心。

## 6. 主要结论与发现

- **记忆体技术主导性能**：仅切换记忆体技术即可使执行时间变化超过一个数量级（最大 19.1×，出现在 histogram 上）。
- **最佳主机主存并不是最佳 PIM 基底**：DDR5 在 bank 级 PIM 中凭借低延迟领跑；而高带宽 HBM 仅在随机访问主导的 BFS 下胜出；面向多宽频道的 GDDR6/LPDDR5 在 bank 级 PIM 下被严重拖慢（如 GDDR6 在 histogram 上比 DDR5 慢 14.2×）。
- **常规内核的 PE 数量超线性扩展**：因为 PE 数量增加带动带宽同步扩展，STREAM triad 从 1 PE 到 64 PE 加速 167 倍（共享内存）至 204 倍（消息传递）。
- **图遍历的集体通信墙**：BFS 在消息传递模式下，rank 数从 16 增至 64 时，执行时间从 24.6M 周期爆炸到 2.42B 周期，展示了内存中分布式 PE 做消息传递时的严重通信瓶颈。
- **全系统能耗结论**：
  - 共享内存卸载在 HBM3 上节省系统能耗（GEMV 0.93×，stencil 0.61×，最高降低 1.6 倍）；
  - 在 DDR5 上最多只能达到持平或更差；
  - 消息传递卸载从不节能（最差

消息传递卸载从不节能（最差情况下系统能耗显著高于主机执行），这表明在追求 PIM 加速时，必须将通信与同步开销纳入能耗预算，否则可能得不偿失。

- **全系统协同的价值**：主机-设备协同仿真揭示了“设备端更快”并不自动等于“端到端更快”。例如，当设备侧 PIM 执行时间很短时，主机端的数据准备、内核启动、PCIe/CXL 链路传输和缓存一致性同步会成为新的瓶颈；反之，若主机端并行度不足，再快的 PIM 也无法被充分喂饱。这种双向耦合效应只有在同一个模拟框架内才能被准确量化。
- **PE 放置的核心权衡**：PE 越靠近存储阵列（如 subarray 级），数据搬运距离越短、能耗越低，但可用面积和 PE 复杂度受限；PE 越靠近记忆体层级顶部（如 rank 或 logic die），集成更灵活、PE 可以更强大，但访问路径变长，且与内存控制器/链接争用加剧。没有全局最优放置点，需根据内核的数据局部性和并行度决定。
- **核心模型保真度的影响**：简单地用 ALU 近似代替完整处理器模型会低估 PE 的时序开销，导致乐观的加速比；使用 in-order 或 out-of-order 核心则能更真实地反映指令级并行和流水线停顿，但功耗显著上升。对于以批量加载/计算为主的简单内核，ALU 模型足够；对于控制流密集或访存不规则的内核，必须使用更高保真度的核心模型。
- **模拟器自身开销**：PIMID 的双域协同设计虽然避免了进程间通信，但周期级网络建模和 McPAT 功耗计算仍会显著拖慢模拟速度；论文并未给出模拟吞吐率（如“每秒模拟多少条指令”），因此对大规模设计空间扫描的实际可用性仍需读者自行评估。

## 7. 局限性与未解决问题

- **缺少与真实 PIM 硬件的直接验证**：论文以 Ramulator2 的 DRAM 时序和 JEDEC IDD 电流作为主要校准锚点，但没有在 UPMEM、Samsung HBM-PIM 或其他真实 PIM 系统上运行同一组内核来验证绝对性能与能耗的准确性。因此，PIMID 的结论更适合用于**相对比较**和设计空间排序，而非预测具体芯片的端到端数值。
- **基准测试规模相对较小**：所有内核均为单次运行、短周期负载（最大工作集 256 MB），没有涉及多程序并发、长时间运行或真实应用级 pipeline；这限制了模拟器在持久化内存、多租户 PIM 场景下的说服力。
- **执行模型的实现粒度较粗**：OpenMP 和 MPI 的语义被映射到设备上的线程/进程抽象，但主机与设备之间的内存一致性、原子操作、消息聚合等细节做了简化；在真实系统中，这些语义的工程实现可能引入额外开销，而 PIMID 只通过链路模型和网络拥塞进行了部分计费。
- **新兴记忆体扫描的容量不一致**：SRAM/NVM 使用 16 MB 工作集，DRAM 使用 256 MB，使得跨记忆体技术的绝对周期数和能耗不能直接横向比较；作者虽然给出了理由，但这削弱了图 4 与图 5 之间的连续性。
- **定性比较代替定量比较**：表 I 展示了 PIMID 在技术覆盖面和模型保真度上的优势，但未与 MultiPIM、PIMSim、PIMeval 等现有模拟器在实际运行时间和能量预测精度上进行对比；因此无法判断 PIMID 的“更高保真度”是否真的转化为更准确的预测。

## 8. 总结与适用场景

PIMID 是一个设计目标明确、架构干净、覆盖面广的 PIM 模拟框架。它最大的贡献在于把记忆体技术、PE 放置、PE 数量、核心模型、主机-设备链路、网络和功率模型统一到一套可配置的模拟流程中，并提供了 OpenMP/MPI 两种执行模型的原生支持。对于以下场景，PIMID 具有明显优势：

- **早期设计空间探索**：在还没有具体芯片实现时，快速比较不同记忆体标准和 PE 放置策略；
- **PIM 架构教学与科研**：提供可复现的 YAML 配置和插件接口，便于后续研究者扩展新记忆体模型或核心模型；
- **全系统能效分析**：能够输出主机、设备、链路、网络各个组件的能耗分解，帮助定位 PIM 系统中的真实瓶颈。

但它并不适合作为“最终周期精确验证工具”：其绝对数值可信度依赖于 Ramulator2/CACTI/NVSim/McPAT 等底层模型的准确性，且缺少与真实硬件的直接对照。因此，建议将 PIMID 视为一个“设计空间排序器”而非“性能预言机”。

总体而言，PIMID 在系统性和可扩展性上明显超越了大多数已有 PIM 模拟器，尽管仍然存在验证不足和工作负载规模较小的遗憾，但其为 PIM 系统研究提供了一个有价值的统一分析和探索平台。
