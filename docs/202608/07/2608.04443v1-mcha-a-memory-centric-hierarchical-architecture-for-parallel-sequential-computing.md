## 摘要
新兴工作负载，如多智能体强化学习（MARL）、大规模神经形态计算和概率图模型，本质上表现出并行-顺序的计算模式。虽然这些任务需要大规模并行性来实现高吞吐量，但它们受到集中到主存的不规则数据访问模式的严重瓶颈制约。因此，传统架构在执行这些工作负载时面临根本性限制，主要表现为全局缓冲区饱和和内存受限瓶颈。为了解决这些挑战，我们提出了内存中心层次化架构（MCHA），一种专为并行-顺序执行定制的可重构硬件解决方案。MCHA 利用层次化通信策略，促进分布式核间数据路由，从而显著降低全局存储器的带宽负担。作为硬件的补充，MCHA 引入了一种新颖的并行-顺序编程模型，该模型利用事件驱动的条件触发器来有效隐藏执行流水线中的数据传播延迟。我们针对一系列多样化的并行-顺序任务对 MCHA 进行基准测试，包括 MARL、电机变量控制和马尔可夫随机场。通过我们开源、周期精确的模拟器进行验证，MCHA 在 MARL 工作负载上相较于 NVIDIA A100 GPU 表现出 153.06 倍到 2456.96 倍的速度提升，同时在其它应用领域保持强大的编程灵活性。此外，该架构成功地将主存访问从 96% 降低到 5.44%。在 28 纳米工艺下综合时，MCHA 实现的面积占用为 2.92mm²，在 200 MHz 下功耗为 115.36 mW。MCHA 已在 https://github.com/carabdis/MCHA 开源。

## Abstract
Emerging workloads, such as Multi-Agent Reinforcement Learning (MARL), large-scale neuromorphic computing, and probabilistic graphical models, intrinsically exhibit parallel-sequential computing patterns. While these tasks demand massive parallelism to achieve high throughput, they are severely bottlenecked by irregular data access patterns centralized to main memory. Consequently, conventional architectures face fundamental limitations when executing these workloads, primarily manifesting as global buffer saturation and memory-bound bottlenecks. To address these challenges, we propose the Memory-Centric Hierarchical Architecture (MCHA), a reconfigurable hardware solution tailored for parallel-sequential execution. MCHA leverages a hierarchical communication strategy that facilitates distributed, inter-core data routing, thereby significantly reducing the bandwidth burden on the global memory. Complementing the hardware, MCHA introduces a novel parallel-sequential programming model that utilizes event-driven conditional triggers to effectively hide data transmission latency within the execution pipeline. We benchmark MCHA against a diverse suite of parallel-sequential tasks, including MARL, motor variable control, and Markov random fields. Validated through our open-source, cycle-accurate simulator, MCHA demonstrates performance speedups ranging from 153.06$\times$ to 2456.96$\times$ over NVIDIA A100 GPUs on MARL workloads, while maintaining robust programming flexibility across other application domains. Furthermore, the architecture successfully reduces main memory access from 96% to 5.44%. When synthesized in a 28 nm process, the MCHA implementation occupies an area footprint of 2.92mm$^2$ and consumes 115.36 mW of power at 200 MHz. MCHA is open-sourced at https://github.com/carabdis/MCHA.

# MCHA：面向并行-顺序计算的内存中心层次化架构

## 1. 核心问题与研究动机

**背景问题：** 新兴工作负载（如多智能体强化学习MARL、大规模神经形态计算、概率图模型以及Bulk Synchronous Parallel（BSP）框架）本质上呈现**并行-顺序计算（PSC）**模式——既需要大规模并行性以提高吞吐量，又在各时间步边界存在严格的同步依赖。这类任务的核心瓶颈在于：

- **不规则数据访问集中到主存**：实体间的频繁细粒度交互导致DRAM访问成为主导操作
- **传统架构的固有缺陷**：在GPU等计算中心架构上，数据移动开销占总操作数的83%~96%（如图1(b)所示），全局缓冲区成为串行瓶颈，缓存一致性开销严重
- **“内存墙”问题**：Gustafson-Barsis定律分析表明，当 `T_compute / T_data-transfer ≪ 1` 时，有效并行加速比S退化为“1”，即无并行收益

**核心挑战：**
1. **全局缓冲区饱和（Global Buffer Saturation）**——缺少核间点对点通信原语，多核竞争集中式全局内存资源
2. **内存受限陷阱（Memory-Bound Trap）**——数据索引与处理在传统架构中刚性耦合，处理单元频繁停滞等待数据

## 2. 方法论

### 2.1 核心思想
MCHA提出了一个**内存中心多芯片计算架构**，核心策略是：将原来串行化的数据传输部分（`T_data-transfer`）并行化，用分布式内存结构替代集中式全局缓冲区，并配以数据驱动编程模型隐藏通信延迟。

### 2.2 架构设计

**（1）计算层——内存中心核心（MCC）**
- 每个MCC集成RISC-V核作为嵌入式编排器，配有SRAM存储体和MMIO FIFO
- 实体状态数据 `x_i` 驻留在本地内存中，最大化数据局部性
- 核间通信通过MMIO FIFO实现，编译后简化为标准load/store操作

**（2）通信层——三级层次化NoC**
- **第1层（块内通信）**：MCC分组为处理块（PB），块内通过高带宽FIFO互连
- **第2层（块间通信）**：邻接PB之间通过2D-mesh拓扑连接，作为主动缓冲区替代多级缓存
- **第3层（芯片间通信）**：跨芯片边界的点对点高带宽连接（如PCIe/UCIe）
- 独立的DRAM Fabric处理片外流量，与核间mesh解耦

### 2.3 数据驱动编程模型
将函数操作分为四种触发类型：

- **内存条件触发**：本地SRAM变量满足逻辑谓词时启动函数
- **相位条件触发**：在同步点切换触发配置，实现动态函数部署
- **输入触发**：消息到达FIFO时激活函数，解耦执行与NoC延迟
- **默认内存扫描**：无外部FIFO输入时自主扫描本地SRAM继续执行

通信被分解为三个异步触发阶段：初始执行 → 索引接收 → 数据检索，从而实现流水线停顿隐藏。

### 2.4 通信协议
- **MMIO FIFO映射**：数据发送编译为store指令，接收编译为load指令，空FIFO返回32位"0"（零签名机制）触发默认内存扫描
- **Type 1消息**：32位单包，支持单跳通信（对应第1层），3位类型ID+5位目标+3字节负载
- **Type 2消息**：可变长突发，头包含路由元数据，后续包全为数据（对应第2、3层）
- **仲裁策略**：基于FIFO的先来先服务（计数器记录等待时间，优先服务等待最久者），相比轮询/随机调度，P99尾延迟降低6.26%~41.8%

### 2.5 部署映射策略
- **局部性感知实体聚类**：基于交互频率将邻居实体映射到同一MCC/PB；动态迁移适应环境变化（如MPE/StarCraft中的块边界自适应调整）
- **脉动阵列映射**：复杂更新函数（如DNN推理）按输入驻留模式部署，支持跳过空值运算
- **吞吐量分析流水线**：提取 `R_pop`（弹出率）和 `R_push`（生产率），通过公式 `N_ideal(i) * R_push(i) = N_ideal(i-1) * R_pop(i)` 确定理想核数比，再按物理资源约束缩放
