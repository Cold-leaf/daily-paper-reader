## 摘要
异构DRAM处理存储器（PIM）-GPU系统有望为解码阶段的巨型语言模型（LLM）推理带来显著的效率提升，尤其是在长输出生成场景中，然而当前的设计实践忽视了决定实际性能的关键因素。通过对多种架构和工作负载（OPT-7B/70B，Mamba2-2.7B/70B）的系统评估，我们揭示了三条基本设计原则：（i）静态功耗（DRAM泄漏、刷新和GPU空闲功耗）可能主导效率计算，导致仅考虑动态功耗的模型在真实部署中高估token/s/W高达3.85倍（Mamba2-2.7B，批大小1，128个输入token，2048个输出token）；（ii）在所有评估的模型和工作负载中，解码性能随通道数单调不减，通常在低批处理工作负载下于高通道数时趋于平台期；在固定容量扫描下，所有模型反而共享一个接近最优的层次配置，而基于注意力的模型在配置错误时受到的惩罚显著更大；（iii）工作负载映射策略提供的改进有限（内核级延迟/能耗最多降低14.0%/17.4%，端到端收益最多5.6%），并非主要瓶颈。显著的效率提升需要系统级的协同优化。这些原则为设计下一代内存加速LLM系统的架构师提供了设计空间指导。

## Abstract
Heterogeneous DRAM-based processing-in-memory (PIM)-GPU systems promise significant efficiency gains for decode-phase large language model (LLM) inference, particularly in long-output generation, yet current design practices overlook critical factors that determine real-world performance. Through systematic evaluation of diverse architectures and workloads (OPT-7B/70B, Mamba2-2.7B/70B), we reveal three fundamental design principles: (i) static power consumption (DRAM leakage, refresh, and GPU idle power) can dominate the efficiency calculus, causing dynamic-only models to overestimate tokens/s/W by up to 3.85X for realistic deployments (Mamba2-2.7B, batch size 1, 128 input tokens, and 2,048 output tokens); (ii) decoding performance is monotonically non-decreasing with channel count across all evaluated models and workloads, generally plateauing at high channel counts for low-batch workloads; under a fixed-capacity sweep, all models instead share a common near-optimal hierarchy configuration, with substantially larger misconfiguration penalties for attention-based models; (iii) workload mapping strategies provide bounded improvements (up to 14.0%/17.4% kernel-level latency/energy reduction, up to 5.6% end-to-end gain) and are not primary bottlenecks. Significant efficiency gains require system-wide co-optimization. These principles provide design-space guidance for architects designing the next generation of memory-accelerated LLM systems.

### 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：
  - 大型语言模型（LLM）推理推高了硬件对内存带宽的需求：GPU在计算方面表现出色，但注意力（attention）、循环状态更新等内存密集型操作受限于带宽瓶颈。
  - 基于DRAM的处理存储器（DRAM-PIM）通过将计算移至数据附近、减少数据搬运，成为有前景的加速路径。异构DRAM-PIM-GPU系统（集成式、CXL互联、NVLink互联等）被视为解码阶段LLM长输出生成场景的理想平台。

- **核心问题**：
  - 现有设计实践忽视了决定实际性能的关键因素，包括DRAM层次组织、静态功耗、工作负载映射和互联选择等，而这些因素以非直观的方式相互作用。
  - 例如，增加DRAM通道数量在工作负载缺乏足够内存级并行性时收益递减；低批次下闲置组件的静态功耗可能完全抵消PIM的吞吐量增益。
  - 现有评估工具（NicePIM、Pimba、PAPI、AttAcc等）都只覆盖部分因素，没有工具能联合捕获静态功耗与层次探索对LLM解码的影响。

- **整体含义**：
  - 本文通过系统级评估揭示三条可操作的设计原则，为设计下一代内存加速LLM系统提供设计空间指导，强调系统级协同优化而非单点优化。

### 二、方法论：核心思想、关键技术细节与算法/公式

- **核心思想**：
  - 联合评估静态功耗、DRAM层次组织、工作负载映射和互联选择四个因素对异构DRAM-PIM-GPU系统LLM解码效率的影响，通过系统级仿真提取普适设计原则。

- **仿真器构建**：
  - 基于ramulator 2（内存）+ AttAcc/Pimba模拟器（系统）进行扩展，新增建模能力包括：DRAM刷新/泄漏静态功耗、灵活的操作映射、集成/共享两种DRAM-PIM-GPU配置，以及不同互联类型。
  - 可捕获PIM执行期间的GPU空闲功耗、传输/计算竞争，以及层次-映射之间的交互。

- **NBPU（近库处理单元）设计**：
  - 参考Pimba/AttAcc架构：默认40通道/1,280存储体层次下，配备640个NBPU，每个NBPU连接两个存储体，运行频率378 MHz，支持MX8点积/乘加运算及累加。
  - 活跃NBPU能耗按执行计算事件计数核算；空闲PIM功耗仅在CXL/NVLink共享配置下计入（已有PIM-HBM的预充电待机功耗 + 平均刷新功耗），不适用于集成式DRAM-PIM。

- **静态功耗建模参数**：
  - GPU上下文活跃功耗：80 W/A100板卡（基于NVML实测）。
  - PIM-HBM待机背景功耗：8.41 W/单元（仅共享配置）。
  - 刷新能量：4.89 nJ/存储体/事件；刷新间隔：3.9 μs。
  - 刷新能量按存储体容量缩放：`E_ref,bank = 4.89 nJ × C_bank / 64 MiB`（64 MiB为参考1,280存储体组织下单存储体容量）。

- **互联模型**：
  - 单次传输延迟：`t_s(k) = L_s + k / B_s`，其中s ∈ {NVLink, CXL}。
  - NVLink3：单向带宽300 GB/s，延迟1.0 μs；CXL/PCIe 6.0：单向带宽120 GB/s，固定延迟180 ns。
  - GPU间张量并行集合通信（8-GPU/70B结果使用）：递归二分/倍增all-reduce模型，`t_AR = 2·log2(P)·L_AR + 2(P-1)/P · k/B_NVLink`，每轮集合延迟L_AR = 6.06 μs。

- **工作负载映射算法（RowLocalChunk）**：
  - 提出一种确定性、局部性感知的映射策略，替代Pimba的基于堆的分配器。
  - 计算流程（Algorithm 1）核心步骤：
    1. 计算行/列块数：`chunk_r ← ⌊atom_sz / elem_w⌋`，`chunk_c ← ⌊page_sz / atom_sz⌋`。
    2. 计算行列网格：`N_r ← ⌈d_model / chunk_r⌉ · B`，`N_c ← ⌈L_max / chunk_c⌉`。
    3. 通过最大余数法（largest-remainder）计算各PIM单元配额。
    4. 按行主序遍历所有块，依次按三阶段选择目标单元：同行所有者（row owner）→ 同列所有者（col owner）→ 最小负载单元。
  - 该策略在保持全局负载均衡的同时，最大程度保留相邻块的空间局部性，减少行切换（row switching）开销。

### 六、主要结论与发现

- **设计原则一：静态功耗可主导能效计算**：
  - 仅考虑动态功耗的模型会高估token/s/W最多3.85×（Mamba2-2.7B，B=1，ISL=128，OSL=2048）。
  - 静态组件（DRAM泄漏、刷新、GPU空闲）在OPT-70B/Mamba2-70B（B=128，ISL/OSL=2048，CXL）中占总系统功耗的66-69%。
  - 在B=1时，默认层次的PIM仅与GPU基线持平；吞吐摊还增益要到B≥32才出现。
  - 集成/CXL/NVLink三种互联方式性能接近，互联选择是次要因素，静态功耗管理才是关键。

- **设计原则二：解码性能随通道数单调非减，但存在平台期；固定容量下存在公共近优配置**：
  - 所有模型/工作负载下性能随通道数单调非减；低批量时通常在32-64通道间趋于平台期。
  - 在固定容量扫描下，所有模型一致以(40,2,4)和(80,1,4)为近优配置（各自峰值0.3%以内）。
  - 但误配置惩罚差异显著：最差配置(2,2,80)下，OPT-7B/OPT-70B仅保留峰值的33.6%/51.6%，而Mamba2-2.7B/Mamba2-70B保留67.3%/76.8%——基于注意力的模型对层次误配置更敏感（惩罚大约2倍于SSM模型）。

- **设计原则三：工作负载映射改进有限，非主要瓶颈**：
  - RowLocalChunk相对于Pimba堆式分配器：内核延迟降低4.4-14.0%，内核能耗降低6.3-17.4%，端到端解码增益仅有0.6-5.6%。
  - 映射仅支配PIM部分，而PIM内核在总解码能耗中占比有限（计入GPU计算、通信和静态空闲功耗后），因此内核级收益被压缩。

- **总体结论**：显著效率提升需要系统级协同优化（静态功耗管理 + DRAM层次配置 + 工作负载映射 + 互联选择），启发架构可重构性需求。
