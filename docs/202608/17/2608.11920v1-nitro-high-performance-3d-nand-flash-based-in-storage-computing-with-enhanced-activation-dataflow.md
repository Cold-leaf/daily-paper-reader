## 摘要
存储内计算（ISC）因其能够缓解主机与存储器之间的数据瓶颈而被视为下一代存储器架构。尽管近年来大型语言模型（LLM）所需的资源显著增加，但存储器密度并未相应扩展。近期，多项研究探索了基于NAND闪存的存内计算（NAND-PIM）方案，以利用存储器的高密度优势。然而，这些方案未处理中间值的数据流/缓冲区，因此简单的方法是在缓慢的闪存阵列中处理这些值。为克服这一限制，我们提出了一种具有增强激活缓冲功能的高性能NAND闪存存储内计算架构。该架构不是使用非常缓慢的闪存阵列来处理中间值，而是将值缓冲在快速的DRAM子系统中。这种方法有效处理了将激活值编程到较慢的TLC NAND闪存时产生的高延迟开销。我们还为NAND-PIM阵列引入了一种分布式数据流方法。该方法通过采用高效的平面内数据映射，最大限度地提高了计算并行性。结果表明，与基线相比，我们提出的架构实现了显著的性能提升，推理延迟最多降低了85%。

## Abstract
In-storage computing (ISC) is considered a next-generation memory architecture for its ability to relieve the data bottleneck between the host and the memory. While the required resources of large language models (LLMs) have increased significantly in recent years, the memory density has not scaled accordingly. Recently, several works have studied NAND flash-based processing-in-memory (NAND-PIM) schemes to exploit the high density of the memory. However, they do not address the dataflow/buffer for the intermediate values, so a simple method is to deal with the values in the slow flash memory array. To overcome such a limitation, we propose a high-performance NAND flash-based ISC architecture with enhanced activation buffering. Instead of using the very slow flash memory array for the intermediate values, our architecture buffers the values in a fast DRAM subsystem. This approach effectively handles the high-latency penalties when activations are programmed into slower TLC NAND flash. We also introduce a distributed dataflow approach for the NAND-PIM array. This approach maximizes computational parallelism by employing efficient intra-plane data mapping. The results show that our proposed architecture achieves significant performance improvements, reducing the inference latency by up to 85% compared to the baseline.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于Transformer的大语言模型（LLM）的参数量呈指数级增长，导致内存容量与内存带宽需求急剧上升。频繁的处理器与存储器之间的数据搬运形成了严重的内存瓶颈，增加了推理延迟并浪费了强大的计算资源。
- **已有方案局限**：存内计算（PIM）被视为缓解内存瓶颈的潜在方案，但DRAM、SRAM、ReRAM等PIM方案受限于存储密度与扩展性，难以满足LLM的容量需求。3D NAND闪存凭借超高存储密度、非易失性和低每比特成本成为候选介质。现有的NAND闪存PIM方案（如3D-FPIM、S-FLASH）主要聚焦于MVM运算本身，使用简化的设计（如小阵列、SLC模式），**未解决LLM推理中大量中间激活值（intermediate activations）的数据流与缓冲问题**。简单做法是将中间值写回慢速TLC NAND阵列，但TLC编程延迟高达数百微秒，形成严重的性能瓶颈。
- **本文目标**：提出一种高性能NAND闪存存储内计算（ISC）架构NITRO，通过引入DRAM缓冲中间激活值、将注意力层计算卸载到DRAM-PIM、并在NAND-PIM阵列中实现分布式数据流，从而大幅降低LLM推理过程中的高延迟惩罚。

### 2. 方法论：核心思想与关键技术细节

#### 2.1 核心思想：异构PIM协同

- 将Transformer计算块根据数据访问特征映射到最合适的PIM子系统：
  - **线性层（Linear Blocks）**：涉及输入激活与静态权重的大规模矩阵乘法（MMM），映射到**TLC NAND-PIM**阵列（权重驻留于高密度闪存，推理中无需编程）。
  - **注意力层（Attention Blocks）**：涉及激活-激活乘法（如QKᵀ、SV），对NAND编程延迟极其敏感，映射到**DRAM-PIM**（或DRAM-less场景下映射到pSLC NAND）。
  - **中间激活缓冲**：K、V等中间矩阵由上一层产生后，快速写入DRAM缓冲，避免写回慢速TLC阵列。

#### 2.2 关键技术细节一：激活DRAM缓冲

- 基线方案中，计算QKᵀ需要先把K矩阵编程进NAND单元（TLC编程时间约1000μs），导致流水线停滞和资源竞争（图4）。
- NITRO将注意力块所需的K、V等中间激活值快速写入DRAM缓冲，并通过DRAM-PIM执行注意力计算，利用DRAM的纳秒级读写延迟（约50–100ns），有效消除编程瓶颈。
- 针对DRAM-less的SSD配置，可用pSLC NAND模式替代，但pSLC虽然比TLC快，依旧明显慢于DRAM。

#### 2.3 关键技术细节二：分布式数据流（Distributed Dataflow）

- **线性层映射**：
  - 权重矩阵经转置后**垂直切分**并分布到多个平面（如将W分为W₀和W₁，分别映射到4个平面的不同组合），利用3D NAND的平面级并行性。
  - 激活矩阵（prefill阶段含多行token）**水平切分**，不同激活子块与权重子块在各平面同时进行MVM运算，减少迭代次数。
  - 解码阶段激活为单向量时，输入向量广播到多个平面生成部分输出后简单拼接，同样实现并行加速。
- **注意力层映射**：
  - DRAM-PIM场景：多个注意力头分布到不同的DRAM bank，通过bank级并行处理多头注意力。
  - pSLC NAND场景：多头键矩阵（K_Hᵀ）采用**对角放置方案**分布在不同BL组，输入Q逐行通过BLS解码器与对应K相乘；受限于BL电流累积约束，一次只能并行处理部分head；SV计算中，因点积方向为token维、chunk较大，单次迭代可并发的V head数量更少，需要更多迭代。

#### 2.4 硬件架构（NITRO整体设计）

- SSD内部集成NAND子系统与DRAM子系统，由SSD控制器管理。
- NAND闪存die包含4个独立平面，每个平面配备行/列解码器、数据/缓存寄存器。
- 新增PIM支持硬件：**BLS解码器**（按输入数据激活NAND字符串）、**带积分器和电容的ADC**（数字化模拟计算结果）、**处理单元（PE）**（数字累加PIM结果），以及连接BL到数据寄存器的**旁路路径**（支持常规读/编程操作）。

#### 2.5 8位权重计算流程

- 权重以INT8量化并编程到TLC单元；采用**符号-数值表示**，7位幅值前填充两个前导零形成9位，分为三部分存至多个物理单元；正权重存入偶BL、负权重存入奇BL。
- 输入激活以2的补码位串行输入，BLS解码器根据输入位激活对应NAND字符串。
- 电流在成对BL上的差分累积经ADC数字化后，PE执行移位与累加（shift-and-add），最终将16位结果拆分存入数据/缓存寄存器并经I/O输出。

### 6. 主要结论与发现

- **激活DRAM缓冲显著降低延迟**：相对3D-FPIM基线，仅激活缓冲即带来平均约4.07×加速；完全优化的NITRO（BL+AB+DD）将推理延迟降至基线约0.003（3D-FPIM）和0.069（S-FLASH），**最多降低99.7%（相对3D-FPIM）和约93.1%（相对S-FLASH）**。
- **吞吐大幅提升**：完整NITRO相对3D-FPIM提升约287×，相对S-FLASH提升约14.5×。
- **能耗显著降低**：完整NITRO相对3D-FPIM降低约98.9%；相对S-FLASH降低约72.6%。
- **pSLC不如DRAM**：pSLC模式下虽比TLC快，但多位数页面布局增加了ADC复用延迟，整体效果不如DRAM缓冲。
