## 摘要
大语言模型（LLM）推理在适应模式、上下文长度和请求并发性方面表现出显著的差异性，这给在存内计算（CIM）加速器上维持高利用率、内存效率和可扩展性能带来了挑战。本文提出了CHIPSMORE，一种多模式多请求LLM推理加速器，它集成了互连计算和CIM，以支持在不同工作负载下的基础模式和低秩适应（LoRA）推理。CHIPSMORE采用异构处理单元，由阻变存储器模拟存内计算（RRAM-ACIM）和静态随机存取存储器数字存内计算（SRAM-DCIM）组成，通过可编程的PE间计算网络（IPCN）互连。一种可组合的分层键值（KV）存储方案根据工作负载需求动态分配路由器暂存器、SRAM-DCIM和嵌入式DRAM（eDRAM）资源，从而支持长上下文和批量推理的可扩展性。此外，一种非复制多请求执行流水线利用请求级并行性而不复制预训练权重，而状态感知的资源重构机制选择性地保留运行时状态并对非活动资源进行电源门控，以提高能效。使用周期精确的软硬件协同仿真进行的评估表明，CHIPSMORE在不同模型大小、上下文长度和批量大小下有效维持高吞吐量，同时保持有利的功耗缩放。与Nvidia H100相比，CHIPSMORE在Mistral-7B推理上实现了高达$2.38\times$的吞吐量提升和$27\times$的能效提升，同时消除了多请求服务中的权重复制。

## Abstract
Large language model (LLM) inference exhibits substantial variability across adaptation modes, context lengths, and request concurrency, creating challenges for maintaining high utilization, memory efficiency, and scalable performance on compute-in-memory (CIM) accelerators. This paper presents CHIPSMORE, a multi-mode and multi-request LLM inference accelerator that integrates compute-in-interconnect and CIM to support both base-mode and low-rank adaptation (LoRA) inference under diverse workloads. CHIPSMORE employs heterogeneous processing elements consisting of resistive RAM analog compute-in-memory (RRAM-ACIM) and static RAM digital compute-in-memory (SRAM-DCIM) interconnected through a programmable Inter-PE computational network (IPCN). A composable hierarchical key-value (KV) memory scheme dynamically allocates router scratchpad, SRAM-DCIM, and embedded DRAM (eDRAM) resources according to workload requirements, enabling scalable support for long-context and batched inference. Furthermore, a non-replicated multi-request execution pipeline exploits request-level parallelism without duplicating pretrained weights, while a state-aware resource reconfiguration mechanism selectively retains runtime states and power-gates inactive resources to improve energy efficiency. Evaluation using cycle-accurate hardware-software co-simulation demonstrates that CHIPSMORE effectively sustains high throughput across varying model sizes, context lengths, and batch sizes while maintaining favorable power scaling. Compared with Nvidia H100, CHIPSMORE achieves up to $2.38\times$ higher throughput and $27\times$ higher energy efficiency on Mistral-7B inference while eliminating weight replication for multi-request serving.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心痛点**：LLM 推理在三个维度上呈现高度动态性——① 适应模式（基础推理 vs LoRA 低秩适配）、② 上下文长度（短/长/超长）、③ 请求并发度（batch size）。这导致传统 CIM（存内计算）加速器难以同时维持高利用率、高能效与可扩展性。
- **矛盾点 1（阶段不匹配）**：Prompt 的 prefill 阶段是矩阵-矩阵（并行密集）计算，而 decode 阶段是单 token 自回归串行生成，二者对硬件资源的需求形态差异巨大，单一优化方向容易顾此失彼。
- **矛盾点 2（KV 缓存压力）**：KV cache 容量随上下文长度与并发请求数线性增长，而对片上 SRAM 容量和层级调度提出严苛要求，长上下文场景下传统局部 SRAM 设计不可扩展。
- **矛盾点 3（多请求并行的权重复制代价）**：已有 CIM 加速器多用权重复制来提高批吞吐，但 RRAM 容量、芯片面积、泄漏功耗与复制因子近似成正比，代价高昂。
- **整体含义**：需要一个从计算、通信、存储到电源管理四个维度统一编排的异构 CIM 系统，在 base-mode 和 LoRA 两种模式下、跨不同上下文长度与批大小都能保持高吞吐和高能效。CHIPSMORE 即为该目标提出的芯片级系统方案。

## 2. 提出的方法论（核心思想与关键技术细节）

**总体架构**：多芯粒（chiplet）系统，每个计算瓦片（Compute Tile, CT）包含 32×32 的 2D 网格 IPCN（Inter-PE Computational Network），每个路由器节点连接一对异构 PE，构成完整的计算-存储-通信单元。

- **持久性感知的计算划分（Persistence-aware Compute Partitioning）**：
  - **静态权重相关操作（SMAC）**：预训练模型权重存入 RRAM-ACIM（256×256 阵列），利用非易失、高密度、高并行特性执行 MVM，权重保持映射后无刷新/重配置开销。
  - **动态数据相关操作（DMAC）**：注意力分数 Q·Kᵀ 等运行时中间张量的计算，在 IPCN 路由器内的计算宏（含部分和累加、激活、DMAC）中直接边移动边计算，减少中间激活搬运，维持数据局部性。
- **可编程 IPCN 设计**：
  - 由网络程序存储器（NPM）+ 配置协处理器（CC）+ 网络主控制器（NMC）+ 单位路由器组成。
  - NPM 采用 Bank1/Bank2 双缓冲，一个 bank 做指令源时另一 bank 由 CC 预加载，掩盖重配置延迟。
  - 自定义 30 位 IPCN ISA 指令字，支持单播/广播通信原语与计算原语；提供 API + 编译器软件工具链。
- **统一空间映射（Unified Spatial Mapping）**：
  - 将 WQ/WK/WV/WO 按 CIM 阵列维度做几何切分后，映射到 RRAM-ACIM；对应的 LoRA 矩阵采用相同几何分解映射到 SRAM-DCIM，保证贡献可以在本地累加，无需重新映射 PE。
- **可组合分层 KV 存储（Hierarchical KV Memory Allocation）**：
  - KV 存储分三级：① 路由器暂存器（最靠近 IPCN/PE，最低延迟）→ ② SRAM-DCIM（16 MiB/CT）→ ③ eDRAM（64 MiB/CT，2T0C 单元，无电容、非破坏读、刷新频率低）。
  - Base 模式下 SRAM-DCIM 被当作 KV 缓存扩展；LoRA 模式下则保留给适配矩阵而退出 KV 池，造成不同模式下的层级分配差异（KV 分配优先级表见原表 II）。
  - 单个 CT 容量不足时，KV 数据通过 UCIe 跨芯粒容量条带化（capacity striping）分布。
- **非复制多请求执行流水线**：
  - 每个 transformer 层静态指派到唯一的权重承载芯粒集群，多个请求在时间上错开注入，形成跨层流水线，从而在解码阶段把请求级并行转化为硬件利用率。
  - PNG 图（Fig. 4）展示了 R1~R4 请求经 P·S1~S5（prefill）和 D·S1~S5（decode token 任务）的交错执行，权重只保留单份，每请求独立维护 KV 状态。
- **状态感知资源重构（State-aware Resource Reconfiguration）**：
  - 区分三类状态：RRAM 里的非易失权重（可断电）、SRAM-DCIM/eDRAM 中的易失 LoRA 参数与 KV 缓存（必须保电）、无关资源。
  - 计算完成后，仅含 LoRA/KV 的集群只保有对应存储资源供电，IPCN 路由器与空闲计算宏被电源门控，实现功耗随活跃计算与保运状态缩放，而非常随模型容量上升。

## 6. 主要结论与发现

- **总体性能**：相对 Nvidia H100（vLLM），CHIPSMORE 在 Mistral-7B 上实现 up to 2.38× 吞吐与 27× 能效（batch=1 时：1112.5 vs 467.3 tokens/s；36.24 vs 1.34 tokens/J），且无需权重复制。
- **批量扩展**：批大小 1→4 时，短上下文下吞吐提升约 2.71×~3.91×，呈亚线性（原因是管线填充/排空开销、单层独占限制与共享通信资源竞争）。
- **上下文扩展**：上下文从 S→XL 使 prefill 注意力 O(T²) 增长、decode KV 访问线性增长，加之 eDRAM 层级被激活的额外延迟，吞吐下降明显。
- **LoRA 开销来源**：LoRA 模式吞吐约相当 Base 模式的 ~95%~99%（多数场景），性能损失主要来自 SRAM-DCIM 被适配矩阵占用导致 KV 被迫使用 eDRAM 的访问开销，而非 LoRA 本身的计算成本。
- **互连不是瓶颈**：即使在 batch=4 的最大负载下，UCIe 利用率仍低于 25%，说明 CHIPSMORE 的局部化数据流是有效的。
- **能耗特性**：平均功耗并非单调随上下文增长（因执行时间增长更快，平均功率可能下降）；增大 batch 通过提高管线占用率普遍改善能效；LoRA 模式因 SRAM-DCIM 活动增强与 eDRAM 访问增多，功耗高于 Base 模式。

## 7. 优点（方法 / 实验设计亮点）

- **多维度联合设计**：首次在单一 CIM 架构中把 LoRA 支持、KV 层次管理、非复制多请求服务、状态感知电源门控统一编排而非孤立优化，面向真实可变负载场景而非单一 benchmark。
- **非复制权重复用思路新颖**：以层间流水线替代权重复制，直接消除 RRAM 容量/面积/泄漏的线性增长，切中多请求服务的核心成本矛盾。
- **SMAC/DMAC 分离清晰**：将“权重持久性”作为任务划分准则，使 RRAM 与 SRAM-DCIM 各得其所，且 IPCN 边通信边计算，结构优雅。
- **SRAM-DCIM 一石二鸟**：既做 LoRA 矩阵计算又可在 Base 模式复用为 KV 存储，提升资源利用率，且不影响空间映射的统一性。
- **KV 层级化设计务实**：三级存储按需启用，平衡了访问延迟与容量扩展，避免了“要么只靠 SRAM 不可扩展、要么只靠 DRAM 延迟高”的两难。
- **实验呈现全面**：既有端到端吞吐/延迟/token 能效，也有内核级指标（TTFT、ITL、UCIe 流量、流水线利用率、面积功耗分解），对架构声明逐条验证，客观透明。

## 8. 不足与局限

- **无硅验证**：全文基于仿真 + 综合，未给出 tape-out 或 FPGA 原型数据，对模拟器精度依赖大；RRAM 工艺偏差、良率、写入能耗等物理机制未建模。

- **缺少消融实验**：没有量化“IPCN 网络计算、状态感知电源门控、分层 KV、SRAM-DCIM 复用”各组件相对基线贡献占比，无法归因收益来源。
