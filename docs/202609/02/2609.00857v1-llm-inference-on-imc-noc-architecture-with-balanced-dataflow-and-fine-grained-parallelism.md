## 摘要
LLM推理已成为一项关键服务，但它对内存带宽、计算密度和通信效率提出了前所未有的需求。虽然IMC是解决内存墙问题的一种有前景的方案，但LLM的异构数据动态性需要互补资源来处理运行时生成的中间数据。此外，LLM中海量的参数要求纵向扩展架构，其中片上数据移动往往是主要的性能瓶颈。本文提出了一种软硬件协同设计框架，将分布式计算、内存和通信统一成一个无缝的处理-通信结构。在硬件方面，我们提出了一个可扩展架构LEAP，它集成了IMC PE、NMC PE和INC。这使得每个硬件层能够执行专门的任务：IMC用于静态权重，NMC用于动态数据，INC用于部分结果归约。在软件方面，我们引入了一个针对LLM服务中关键指标（包括吞吐量和延迟）优化的划分、映射和调度框架。为解决预填充和解码阶段的不同计算强度，我们提出了一种预填充-解码分离方法，该方法动态重构PE组织形式以最大化资源利用率。与商用GPU平台相比，所提出的架构在吞吐量和能效上分别实现了 $\geq{}1.52\times$ 和 $24.91\times$ 的提升。

## Abstract
LLM inference has become an essential service, yet it imposes unprecedented demands on memory bandwidth, computational density, and communication efficiency. While IMC is a promising solution to the memory wall issue, the heterogeneous data dynamicity of LLM requires complementary resources to handle intermediate data generated during run-time. Furthermore, the massive number of parameters in LLM necessitates scale-up architectures where on-chip data movement is often the primary performance bottleneck. This article presents a hardware-software co-design framework that unifies distributed compute, memory, and communication into a seamless processing-communication fabric. On the hardware side, we propose a scalable architecture, named LEAP, that integrates IMC PE, NMC PE, and INC. This allows each hardware layer to execute specialized tasks: IMC for static weights, NMC for dynamic data, and INC for partial result reduction. On the software side, we introduce a partitioning, mapping, and scheduling framework optimized for key metrics in LLM serving, including throughput and latency. To address the distinct computational intensities of the prefill and decode phases, we present a prefill-decode disaggregation approach that dynamically reconfigures PE organizations to maximize resource utilization. Compared to commercial GPU platforms, the proposed architecture provides a throughput and an energy efficiency improvement of $\geq{}1.52\times$ and $24.91\times$, respectively.

### 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLM）推理已成为现代工业与消费级应用的核心服务，但对内存带宽、计算密度和通信效率提出了极高的要求。
- **核心问题**：针对以存内计算（IMC）为主的加速器，存在三个关键瓶颈：
  1. **硬件挑战 1**：LLM 推理包含海量静态预训练权重和运行时生成的动态中间数据（如激活值、Q/K/V 矩阵），IMC 擅长处理静态权重，但动态数据需要额外资源，因此需要"IMC+X"异构架构。
  2. **硬件挑战 2**：单个 IMC PE 容量小（KB 级），支撑大规模 LLM 需要跨大量 PE 的规模扩展，导致片上通信（即部分结果聚合与归约）成为性能瓶颈，需要在 NoC 路由器中集成计算能力（INC）。
  3. **软件挑战**：在异构计算与存储资源上优化矩阵分区、空间映射与数据流路由极为困难；同时，prefill 阶段和 decode 阶段的计算特征差异巨大，还需处理多请求并发调度的需求。
- **整体含义**：本文提出了一种软硬件协同设计框架，将分布式计算、存储与通信统一为一种无缝的处理—通信结构，为目标 IMC 架构下的 LLM 推理提供了覆盖操作级、阶段级和请求级的系统性优化方案。

### 2. 论文提出的方法论

#### 2.1 硬件架构：LEAP

LEAP 是一种可扩展的"IMC+NMC+INC"统一架构，每个宏单元（macro）包含 IMC PE、路由器（内嵌 NMC 与 INC 资源）。资源分工如下：

| 资源类型 | 执行的运算 | 说明 |
| --- | --- | --- |
| IMC PE | DynStaMM（DSMM，静态权重 × 动态矩阵） | 存储静态权重并执行矩阵乘法 |
| NMC（路由器内 scratchpad + 乘加逻辑） | DynDynMM（DDMM，动态矩阵 × 动态矩阵） | 存储动态数据并执行注意力机制中的 QK^T 和注意力分数 × V 运算 |
| INC（路由器内归约单元，IRCU） | 部分结果归约 | 在数据包路由过程中执行归约运算，降低通信开销 |

#### 2.2 两种工作模式

- **LEAP-A（Aggregated）**：prefill 与 decode 共享硬件资源，所有宏同构，各含 IMC PE 与路由器。
- **LEAP-D（Disaggregated）**：prefill 区域宏与 LEAP-A 相同，decode 区域宏则去掉 IMC PE，仅保留更大的 scratchpad 与路由器。这一设计充分利用 decode 阶段仅需动态矩阵运算（注意力部分）的特性。

#### 2.3 软件框架

- **分区（Partitioning）**：按照 IMC PE 尺寸（128 × 128 交叉阵列）和 scratchpad 容量对权重矩阵与动态矩阵进行行列方向的分块。
- **映射（Mapping）**：
  - 层内映射采用启发式约束：子矩阵放置在连续矩形区域、按行主序/列主序展开。Q/K/V 权重采用列主序映射，O 权重采用行主序映射。
  - 层间映射采用蛇形（serpentine）拓扑，使 autoregressive decode 的层间 token 传递路径最短。
- **数据流模式**：定义了广播（Broadcast）、归约（Reduce）、ReduceScatter、AllGather、AllReduce 等确定性集体通信模式。在编译期确定数据流路径，减少运行时的控制和仲裁开销。
- **PD 分离（Prefill-Decode Disaggregation）**：将 prefill 和 decode 放在不同的 PE 区域中独立执行，并在 KV 缓存传输与现有 prefill 计算之间做计算—通信重叠，消除关键路径开销。
- **批处理调度**：针对批大小 2 的请求并发场景，分析了 prefill 与 decode 阶段访问 IMC 权重资源时的冲突与调度策略。

#### 2.4 关键技术分析

- **静态矩阵行/列方向归约**：Q/K 采用行主序归约，V 采用列主序归约（图 7），优化了 partial sum 的片上汇聚方向。
- **流水线重叠**：AllGather 与后续 MAC（乘累加）操作重叠执行，掩盖通信延迟（图 7(c)）。
- **循环 KV 存储机制**：decode 阶段上下文的 KV 向量以循环方式追加到 scratchpad 的指定映射区域，保证本地存储均衡利用。

### 6. 论文的主要结论与发现

- **GPU 对比收益**：与 A100 相比，LEAP-A 吞吐量提升 2.55×、能效提升 71.94×；与 H100 相比，LEAP-D 在 8B 模型下吞吐量提升 1.52×、能效提升 24.91×。能效提升主要源于最小化的数据移动和分布式计算-存储组织。
- **PD 吞吐量差距收窄**：LEAP-A 中 decode 吞吐量比 prefill 低 4~6 倍；LEAP-D 通过去耦合和广播当前 token 到 decode 区域的所有 PE，显著弥合了二者差距。
- **次线性吞吐退化**：模型规模从 1B 扩展到 8B 时（约 8 倍参数量增长），吞吐只以近似线性因子退化，原因在于广播/归约关键路径只随行向/列向规模的缩放，而非总参数量的缩放。
- **关键路径归因**：IMC 运算不是瓶颈，延迟主要来自数据搬移和 IRCU 中 DDMM 操作；64-bit 包宽 + 16 路 IRCU 并行位于性能前沿，接近最优。
- **批处理并非一贯最佳**：批处理（批大小 2）显著改善 TTFT，但以 TPOT 增加为代价，适合 TTFT 敏感型应用；非批处理更利于 TPOT 优化，二者定位为互补模式。

- **软硬件协同设计视角完整**：从操作级、阶段级到请求级的三层覆盖，在 IMC 架构文献中较为罕见。
