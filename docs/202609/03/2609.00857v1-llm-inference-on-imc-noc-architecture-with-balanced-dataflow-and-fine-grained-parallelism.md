## 摘要
LLM推理已成为一项基本服务，但它对内存带宽、计算密度和通信效率提出了前所未有的要求。虽然IMC是解决内存墙问题的一种有前景的方案，但LLM的异构数据动态性需要互补资源来处理运行期间生成的中间数据。此外，LLM中大量的参数需要扩展架构，其中片上数据移动通常是主要的性能瓶颈。本文提出了一个硬件-软件协同设计框架，将分布式计算、内存和通信统一到一个无缝的处理-通信结构中。在硬件方面，我们提出了一种名为LEAP的可扩展架构，它集成了IMC PE、NMC PE和INC。这使得每个硬件层能够执行专门的任务：IMC处理静态权重，NMC处理动态数据，INC处理部分结果归约。在软件方面，我们引入了一个针对LLM服务中关键指标（包括吞吐量和延迟）优化的分区、映射和调度框架。为了解决prefill和decode阶段不同的计算强度，我们提出了一种prefill-decode分离方法，该方法动态重新配置PE组织以最大化资源利用率。与商用GPU平台相比，所提出的架构提供了≥1.52倍的吞吐量提升和24.91倍的能效提升。

## Abstract
LLM inference has become an essential service, yet it imposes unprecedented demands on memory bandwidth, computational density, and communication efficiency. While IMC is a promising solution to the memory wall issue, the heterogeneous data dynamicity of LLM requires complementary resources to handle intermediate data generated during run-time. Furthermore, the massive number of parameters in LLM necessitates scale-up architectures where on-chip data movement is often the primary performance bottleneck. This article presents a hardware-software co-design framework that unifies distributed compute, memory, and communication into a seamless processing-communication fabric. On the hardware side, we propose a scalable architecture, named LEAP, that integrates IMC PE, NMC PE, and INC. This allows each hardware layer to execute specialized tasks: IMC for static weights, NMC for dynamic data, and INC for partial result reduction. On the software side, we introduce a partitioning, mapping, and scheduling framework optimized for key metrics in LLM serving, including throughput and latency. To address the distinct computational intensities of the prefill and decode phases, we present a prefill-decode disaggregation approach that dynamically reconfigures PE organizations to maximize resource utilization. Compared to commercial GPU platforms, the proposed architecture provides a throughput and an energy efficiency improvement of $\geq{}1.52\times$ and $24.91\times$, respectively.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想

提出 **LEAP** 架构，将三种基本资源集成进统一的处理—通信结构中：
- **IMC PE**：负责对静态权重的矩阵乘法（DSMM，静态—动态矩阵乘）；
- **NMC PE**（近内存计算单元，即路由器内的Scratchpad + MAC逻辑）：存储动态数据，并负责对动态矩阵的乘加（DDMM，动态—动态矩阵乘）；
- **INC**（网络内计算，路由器内置归约单元）：在网络中进行部分和归约，减少数据传输量。

### 2.2 系统组织

- 采用**二维网格NoC（Mesh NoC）**。每个PE与路由器组成一个“macro”（宏单元），可通过模块复制进行规模扩展。
- 提供两种运行模式：
  - **LEAP-A（聚合模式）**：prefill与decode共享均匀部署的全部硬件资源；
  - **LEAP-D（分离模式）**：prefill区域保留IMC PE + 路由器；decode区域不设IMC PE、扩展Scratchpad容量（以对应原IMC所存权重的容量），从而实现片上预填充—解码物理解耦。

### 2.3 矩阵分区策略（Partitioning）

- 基于PE与Scratchpad容量，按行/列方向对权重矩阵与动态矩阵进行**细粒度切分**，类似于GPU场景中“张量并行 + 上下文并行”的片上化实现，但粒度更精细、通信频率更高。
- 权重矩阵切分尺寸由IMC crossbar规格决定；动态矩阵切分尺寸由IRCU（路由器内计算单元）带宽与Scratchpad容量决定。

### 2.4 映射策略（Mapping）

- **层内映射（Intra-layer mapping）**：采用启发式规则（如：同一矩阵子块映射到连续矩形区域、按行主序或列主序展开等）降低搜索空间。
  - 注意力层映射到 2⌈D/C⌉ × 2⌈D/C⌉ 宏阵列：Q/K/V按列主序（inter-tile），O按行主序（inter-tile），V在tile内部转置但tile间不转置。
- **层间映射（Inter-layer mapping）**：采用**蛇形（serpentine）拓扑**排布各层，以最小化自回归解码时“最后一层输出token”传回“第一层输入”的传输开销；FFN层计算需求与注意力层相似，使逐层资源规划保持规则化。

### 2.5 数据流定义

将LLM推理过程中的片上数据移动统一归纳为多种确定性集合通信模式：**Broadcast、Reduce、ReduceScatter、AllGather、AllReduce**等。因所有数据流在编译期可确定，因此无需运行时仲裁，控制开销低，并可叠加流水线技术以覆盖通信与计算时间。

### 2.6 执行调度与P/D解耦

- **Prefill（预填充）模式**：采用“广播输入token → IMC计算 → RPU间ReduceScatter → K/V中转（AllGather）→ NMC完成QK^T与注意力分数计算 → V加权 → O聚合”的流程；大量步骤通过流水线重叠通信与计算。
- **Decode（解码）模式**：每个迭代只有一个token参与计算，通信模式从ReduceScatter退化为Reduce；逻辑分量被广播至全部PE，扩大并行度。
- **PD分离（LEAP-D）**：prefill区域算完后，KV缓存同时传输至decode区域，因与既有AllGather通信重叠，关键路径无额外开销。
- **请求级批量调度**：支持batch size为2的并发请求调度，讨论了两个请求在prefill和decode区域的竞争、暂停/恢复机制。

## 6. 论文的主要结论与发现

1. **LEAP能效显著优于GPU**：
   - 相比A100，吞吐量提升≥2.55×，能效提升≥71.94×；

3. **模型规模扩展造成的吞吐下降呈亚线性**：关键路径仅随横向扩展维度的某两项而非三者乘积增长，说明该架构具有良好的可扩展性。
4. **关键路径瓶颈在数据搬运与DDMM计算**，而非IMC侧计算；通过优化路由数据位宽与IRCU并行度可逼近Roofline性能前沿。
5. **批量（batching）并非普适最优**：批处理可显著改善TTFT，但会恶化TPOT；应根据应用目标选择“批处理”或“单请求”模式。

## 7. 优点

- 提出了较完整的**三层软硬件协同框架**：操作级（运算类型分工）→ 阶段级（prefill/decode分离）→ 请求级（批处理调度），系统性强。
- 计算资源分工理论清晰：IMC对静态权重、NMC对动态中间数据、INC对部分和归约，切中了LLM推理数据动态性与IMC特性的核心矛盾。
- 首次将这类“IMC+NMC+INC”融合架构与PD disaggregation结合在片上实现，对IMC权重量分布局限进行了深入分析。
- 数据结构与其通信模式归纳为确定性集合通信（Broadcast/Reduce/AllReduce等），实现编译期可确定数据流，降低运行时控制及网络拥塞代价。
- 提出灵活的“统一宏单元—规则扩展”模板，保持面积分布不随规模膨胀而失衡。
- 能耗与面积数据来源可靠度高（综合、布局布线、CACTI多工具交叉验证），对比实验多视角覆盖（端到端、关键路径、能耗/面积分解、Roofline分析等）。

## 8. 不足与局限

- 评估的最大规模模型为13B，未验证更大参数规模（如70B+）权重的跨芯片/跨die扩展方案。
- 请求级实验只处理到batch size=2，与生产级LLM推理系统常见的数百并发差距显著。
- 数据冲突与“确定性数据流”建立于理想运行条件下，对真实工作负载的中断、网络拥塞、负载抖动等动态鲁棒性未见充分讨论。
- 对RRAM等器件的非理想因素（如有限精度噪声、写入耗时/能量、良率缺陷、温度变化等）未建模，存在一定过度理想化风险。
- 与GPU平台的高层指标对比中，未给出GPU侧相应能耗测试协议的完全一致条件（如同卡多流调度、kernel融合方式、PD分离配置等），公平性需谨慎解读。
- 该架构针对Decoder-only自回归LLM优化，未能验证对其他结构（编码器、多模态模型等）的通用适用性。
- 没有流片验证，构建于较高层次的RTL + 架构级工具的建模证据，距离芯片实物性能尚有差距。
