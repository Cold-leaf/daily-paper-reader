## 摘要
LLM推理已成为一项基本服务，但它对内存带宽、计算密度和通信效率提出了前所未有的要求。虽然IMC是解决内存墙问题的一种有前景的方案，但LLM的异构数据动态性需要互补资源来处理运行时生成的中间数据。此外，LLM中大量的参数需要扩展架构，其中片上数据移动通常是主要的性能瓶颈。本文提出了一个硬件软件协同设计框架，将分布式计算、内存和通信统一到一个无缝的处理-通信结构中。在硬件方面，我们提出了一种名为LEAP的可扩展架构，它集成了IMC PE、NMC PE和INC。这允许每个硬件层执行专门的任务：IMC用于静态权重，NMC用于动态数据，INC用于部分结果归约。在软件方面，我们引入了一个针对LLM服务中关键指标（包括吞吐量和延迟）优化的分区、映射和调度框架。为了解决预填充和解码阶段不同的计算强度，我们提出了一种预填充-解码分离方法，该方法动态重新配置PE组织以最大化资源利用率。与商业GPU平台相比，所提出的架构提供了$\geq{}1.52\times$的吞吐量提升和$24.91\times$的能效提升。

## Abstract
LLM inference has become an essential service, yet it imposes unprecedented demands on memory bandwidth, computational density, and communication efficiency. While IMC is a promising solution to the memory wall issue, the heterogeneous data dynamicity of LLM requires complementary resources to handle intermediate data generated during run-time. Furthermore, the massive number of parameters in LLM necessitates scale-up architectures where on-chip data movement is often the primary performance bottleneck. This article presents a hardware-software co-design framework that unifies distributed compute, memory, and communication into a seamless processing-communication fabric. On the hardware side, we propose a scalable architecture, named LEAP, that integrates IMC PE, NMC PE, and INC. This allows each hardware layer to execute specialized tasks: IMC for static weights, NMC for dynamic data, and INC for partial result reduction. On the software side, we introduce a partitioning, mapping, and scheduling framework optimized for key metrics in LLM serving, including throughput and latency. To address the distinct computational intensities of the prefill and decode phases, we present a prefill-decode disaggregation approach that dynamically reconfigures PE organizations to maximize resource utilization. Compared to commercial GPU platforms, the proposed architecture provides a throughput and an energy efficiency improvement of $\geq{}1.52\times$ and $24.91\times$, respectively.

### 1. 核心问题与研究动机
- **研究背景与核心问题**：LLM推理在服务端和边缘端均面临严重的**存储墙（Memory Wall）**问题，即存储带宽成为计算性能的瓶颈。大模型的海量权重与动态中间数据（如激活值、KV Cache）需要海量的片上/片外数据搬运。
- **硬件层面的挑战**：
    - **数据特性混合**：LLM推理包含静态权重（pre-trained weights）和运行时生成的动态数据（activations）。传统的存内计算（IMC）虽然对静态权重（DSMM）有极高的计算效率，但难以高效处理动态数据（DDMM），需要"IMC+X"架构。
    - **可扩展性受限**：单个IMC PE的容量（如RRAM crossbar通常限制在128x128）无法容纳大型模型。大规模矩阵运算必须切分至数千个PE上执行，这导致对**片上网络（NoC）**的通信带宽和部分和归约能力提出了极高要求。
- **软件层面的挑战**：
    - **硬软件协同设计复杂**：如何在异构且分布式的"IMC+NMC"NoC架构上进行高效矩阵切分、空间映射和数据流路由，是一个难题。
    - **多粒度服务指标差异化**：LLM推理服务需要同时优化吞吐量（throughput）和延迟（latency），且性能需求在**请求级**（不同请求）和**阶段级**（prefill和decode阶段）存在根本冲突。

### 2. 方法论与关键技术细节
论文的核心贡献是提出了一个名为**LEAP**的硬件-软件协同设计框架。
- **硬件架构**：
    - **统一处理-通信结构**：LEAP集成了三种计算/存储资源：
        - **IMC PEs**：处理与**静态权重**相关的矩阵乘法（DSMMs）。
        - **NMC PEs** (在路由器内)：利用Scratchpad存储并处理**动态矩阵**（DDMMs，如attention中的Q·K^T和P·V）。
        - **INC** (In-Router Computing Unit, IRCU)：在NoC路由器中集成算术逻辑，专门用于**部分结果归约**，以减少数据搬运。
    - **网络拓扑**：采用2D Mesh NoC，由多个"宏"（Macro）组成，每个宏由一个IMC PE和一个带NMC/INC功能的路由器构成。这种模块化设计便于尺度扩展。
    - **两种工作模式**：
        - **LEAP-A（聚合模式）**：所有宏均同构，含有相同的IMC和NMC资源，同时处理prefill和decode请求。
        - **LEAP-D（解耦模式）**：将硬件分为**prefill区域**（包含IMC和NMC资源）和**decode区域**（不包含IMC PE，但具有更大的Scratchpad容量）。
- **软件框架**：
    - **分区（Partitioning）**：将权重矩阵行和列方向切分到不同PE；将动态矩阵分区到scratchpads。分区大小与PE运算能力及NoC带宽相关。类似tensor parallelism但粒度更细。
    - **映射（Mapping）**：
        - **层内映射**：基于启发式规则，将同一原始矩阵的子矩阵放在邻近、矩形区域，以避免拥塞。通过对Q、K、V和O矩阵的特定排布，最小化通信开销。
        - **层间映射**：采用蛇形（serpentine）拓扑方式映射多层的decoder，以支持decode阶段的自回归特性。
    - **数据流模式（Dataflow Orchestration）**：定义了**广播（Broadcast）**、**归约（Reduce）**、**ReduceScatter**等核心集合通信模式。所有数据流在编译期就已确定（deterministic），降低了运行时NoC的控制和仲裁开销。
    - **流水线化**：显式设计计算与通信的重叠（如`AllGather`与`MAC-3`的重叠），以隐藏数据移动延迟。
- **Pre-fill/Decode分离与Batching处理**：针对prefill（高计算强度）和decode（高带宽需求）的不对称性，通过LEAP-D配置实现硬件上的解耦，并额外讨论了通过批大小2的batching来管理**并发请求**。

### 7. 优点与亮点
1.  **系统层面的完整性**：提出了一套从基础硬件（分布式ISP）映射到OS/Runtime（调度）的完整生态，贯穿执行操作的数学逻辑（运算器）直至NoC路由器层面的同步。
2.  **对计算数据流的创新**：在NoC层应用INC（网内计算）思想，将路由部分计算转化为计算资源和归约引擎，有效减轻数据聚合的阻塞情形。
3.  **预填充-解码分离（LEAP-D）架构**：在IMC环境展示并实证验证了对预处理/解码在物理/架构层面解耦的优越性——这是服务于重要LLM推理场景的核心策略。该设计明确保留静态IMC权重在prefill区域，将KV缓存动态分配于decode区域以实现硬件专门化。
4.  **确定性数据流**：在编译期强制限定了数据包的路由模式和缓存/节点访问，而不是动态运行时的指令调度。这正是能以非常低芯片开销、极高能量效率和低控制延迟提高确定性性能的核心。
5.  **注意力机制专用优化调度**：在循环去回化上细致分析了FlashAttention，以实现循环单次访问并重叠输出收集路径（用流水线）以提高复用性。

### 8. 不足与局限性
1.  **基准测试覆盖**：没有对抗现有最佳设计的独立AI加速器（如WaferLLM、PD-Wafer、HALO等）基准测试对比。只与绝对巨头（GPU）对比以及基于公开数据的数据表比较，说服力有限。
2.  **未引入软件领域的SOTA**：使用批处理调度策略，并选择简单的提前状态分区分派。未能整合当前的动态批处理、分布式交换（preshing）、内存实时重分配算法，同时没有涉及长KV Cache上下文和新颖的KV Cache压缩（如具有优化的GPU级稀疏性）。
3.  **静态模型映射**：固定模型（或线性扩展）在框架进行了静态布置，对模型的服务到服务切换未提供异构权衡（无迁移成本考虑）。要求存储于内存中的模型权重保持恒定。
4.  **局限性的近似**：使用每个crossbar基于RRAM的宏。针对模拟中使用的时钟/频率缩放（如20GHz吞吐率评估或从45nm/IMC工艺数据组合推算7nm工艺）尚未用硅流片验证设计实现——跨不同工艺节点组合功耗和面积存在明显误差，因此绝对能效数据存在夸大风险，尤其对数字部分。
5.  **预填放大效应**：相较于GPU，在预填-解码拆分情况下GPU的预填充+处理拥有更大的延迟库。关注点仅在单一PE实例内。跨芯片的调用（例如同时跨多个PE阵列）未考虑对总线带宽的更高要求，这可能使更大模型/更长上下文的PE阵列组织不太有效。
6.  **忽略分解分解所带来的基础设施开销**：从解耦编解码转移到NoC层面的通信，未考虑较大KV缓存的间链接和排队延迟预算的代价——这实际可能破坏预填充和解码工作负载之间的隔离。
