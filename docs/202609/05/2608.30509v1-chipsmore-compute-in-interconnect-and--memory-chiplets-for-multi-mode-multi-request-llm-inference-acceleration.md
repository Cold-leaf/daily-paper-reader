## 摘要
大语言模型（LLM）推理在适应模式、上下文长度和请求并发性方面表现出显著差异，这给在存内计算（CIM）加速器上维持高利用率、内存效率和可扩展性能带来了挑战。本文提出CHIPSMORE，一种多模式多请求LLM推理加速器，它集成了互连内计算和CIM，以支持不同工作负载下的基础模式和低秩适应（LoRA）推理。CHIPSMORE采用由电阻式RAM模拟存内计算（RRAM-ACIM）和静态RAM数字存内计算（SRAM-DCIM）组成的异构处理单元，并通过可编程的PE间计算网络（IPCN）互连。一种可组合的分层键值（KV）内存方案根据工作负载需求动态分配路由器暂存器、SRAM-DCIM和嵌入式DRAM（eDRAM）资源，从而支持长上下文和批量推理的可扩展实现。此外，一种非复制式多请求执行流水线在不复制预训练权重的情况下利用请求级并行性，而状态感知的资源重配置机制有选择地保留运行时状态并对非活动资源进行电源门控，以提高能效。使用周期精确的软硬件协同仿真进行的评估表明，CHIPSMORE在不同模型大小、上下文长度和批大小下均能有效维持高吞吐量，同时保持良好的功耗扩展性。与Nvidia H100相比，CHIPSMORE在Mistral-7B推理上实现了高达$2.38\times$的吞吐量提升和$27\times$的能效提升，同时消除了多请求服务中的权重复制。

## Abstract
Large language model (LLM) inference exhibits substantial variability across adaptation modes, context lengths, and request concurrency, creating challenges for maintaining high utilization, memory efficiency, and scalable performance on compute-in-memory (CIM) accelerators. This paper presents CHIPSMORE, a multi-mode and multi-request LLM inference accelerator that integrates compute-in-interconnect and CIM to support both base-mode and low-rank adaptation (LoRA) inference under diverse workloads. CHIPSMORE employs heterogeneous processing elements consisting of resistive RAM analog compute-in-memory (RRAM-ACIM) and static RAM digital compute-in-memory (SRAM-DCIM) interconnected through a programmable Inter-PE computational network (IPCN). A composable hierarchical key-value (KV) memory scheme dynamically allocates router scratchpad, SRAM-DCIM, and embedded DRAM (eDRAM) resources according to workload requirements, enabling scalable support for long-context and batched inference. Furthermore, a non-replicated multi-request execution pipeline exploits request-level parallelism without duplicating pretrained weights, while a state-aware resource reconfiguration mechanism selectively retains runtime states and power-gates inactive resources to improve energy efficiency. Evaluation using cycle-accurate hardware-software co-simulation demonstrates that CHIPSMORE effectively sustains high throughput across varying model sizes, context lengths, and batch sizes while maintaining favorable power scaling. Compared with Nvidia H100, CHIPSMORE achieves up to $2.38\times$ higher throughput and $27\times$ higher energy efficiency on Mistral-7B inference while eliminating weight replication for multi-request serving.

## 1. 核心问题与研究动机（背景与整体含义）

### 研究背景
- LLM 推理涉及两个独立阶段：**预填充（prefill）阶段**和**解码（decode）阶段**，两阶段的计算与访存特征截然不同。
- 推理负载在**三个维度**上存在显著变化：适应模式（基础模式 vs. LoRA 模式）、上下文长度（context length）、请求并发度（request concurrency）。
- KV cache 容量随上下文长度和并发请求数**线性增长**，长期多请求场景下可能超出单一 SRAM 层级的容量边界。
- 基础模式下静态预训练权重适合存储在 RRAM（读写耐用性受限、写能耗高）；LoRA 适配矩阵需要快速可重配置能力，适合 SRAM 数字 CIM。
- **现有 CIM 加速器局限**（详见 Table I）：
  - 绝大多数系统仅支持其中一两种场景，缺乏对适应模式、上下文长度和请求并发三者的联合优化；
  - 多请求吞吐扩展往往通过**复制权重**实现，导致 RRAM 容量、片数量和面积按复制倍数线性增加；
  - KV 存储一旦仅依赖本地 SRAM，则规模扩展受限，无法适应长时间高并发的 KV 需求；
  - 缺乏状态感知的功耗管理机制，无法有效控制静态功耗。

### 核心问题表述
> 在一个统一架构中，如何同时兼顾**适应模式切换、KV 内存层级扩展、请求级并发执行**和**功耗优化**，以实现高效的 LLM 服务？

## 2. 论文提出的方法论（核心思想、关键技术细节）

### 2.1 整体思路：工作负载导向的资源协调框架
CHIPSMORE 采用四级协作机制（统一空间映射、分层 KV 分配、非复制多请求流水线、状态感知重构），围绕三个重要原则展开：

- **持久感知的计算分区**：静态权重运算（SMAC）放在 CIM 宏内执行；动态中间激活的运算（DMAC）放在互连路由器的计算宏中执行；
- **计算-通信-存储一体化**：通过 IPCN 在数据移动中协同计算，减少中间张量搬运；
- **动态内存资源调度**：内存分级（router scratchpad → SRAM-DCIM → eDRAM）按工作负载实时分配。

### 2.2 硬件架构组成

#### (a) 异构处理元件（PE）
- **RRAM-ACIM（宏规格 256×256）**：存储并处理静态预训练权重。非易失、高密度，支持高并行 MVM，权重无需重新加载；
- **SRAM-DCIM（宏规格 256×64）**：功能双用——LoRA 矩阵存储计算，无 LoRA 时作为辅助 KV 存储/通用片上存储；
- 每个 PE 内两种宏都执行 SMAC 操作，但按参数更新频率选择存储载体。

#### (b) 可编程 PE 间计算网络（IPCN）
- **拓扑**：2D mesh，每个单位路由器连接一对异构 PE；
- **三大组件**：
  - **NPM（网络程序存储器）**：双缓冲（Bank1/Bank2）指令存储，每行包含两个命令（CMD1/CMD2）与命令选择掩码/重复次数（CFR），减少程序存储开销；
  - **配置协处理器（CC）**：运行时从系统内存装载 IPCN 程序，无中断更新第二缓冲，降低配置开销；
  - **网络主控制器（NMC）**：顺序取指、译码、生成控制信号，管理指令迭代与执行顺序；
- **计算路由器**：数据 I/O 端口（4 个平面 + AXI-Stream 适配器）带 FIFO，内嵌计算宏执行**部分和、激活函数、DMAC**（如 Q·Kᵀ）；
- **IPCN ISA**：30 位控制指令字，支持 unicast/broadcast 等通信原语与计算原语，提供编译器和 API 支持。

#### (c) eDRAM（嵌入式 DRAM）
- **结构**：2T0C（两晶体管零电容）结构、非破坏读、低刷新频率；
- **作用**：第三级“容量导向”（capacity-oriented）KV 存储；每 CT 容量 64 MiB，刷新时间 10 ms。

#### (d) 跨片通信（Inter-CT Communication）
- 多个计算片通过 **UCIe** 连接，每 CT 含 2 个 UCIe 端点，每个端点 16 lanes；
- 总体上，UCIe 用作跨 CT 架构的规模化扩展手段，同时保持片内局部性。

### 2.3 关键方法论细节

#### (a) 统一空间映射
- 沿用 LEAP 与 PRIMAL 方案，把 W_Q、W_K、W_V、W_O 与 LoRA 矩阵按相同几何分区，在 RRAM 与 SRAM 上保持空间对应；
- 中间张量（Q、K、V、O）存放在对应权重分区的路由- PE 对分配的本地路由器暂存中，实现最小通信；
- 该映射在所有工作模式下保持不变，不因 LoRA/基本切换而重配置。

#### (b) 层级式 KV 内存分配策略
- 三级优先级：
  1. **Router scratchpad**（最靠近 IPCN 和 PE，零跳低频访问）；
  2. **SRAM-DCIM**（基础模式释放 LoRA 占有率后用于 KV）；KV
  3. **eDRAM**（所有更高容量溢出时才启用）；
- KV 容量估算公式：

  C_KV = B·T·L·(2·N_KV·d_head)·b_KV / 8（字节）

  其中 B 为批量、T 为保留上下文长度、L 为注意力层数、N_KV 为 K/V 头数、d_head 为头维、b_KV 为量化位宽；
- **模式相关分配**：基础模式下，SRAM-DCIM 纳入 KV 池；LoRA 模式下 SRAM-DCIM 被保留给 LoRA 矩阵，不在 KV 内参与。
- 单 CT 容量不满足需求时，以容量分条方式跨片分配 KV（按跨片容量条带化）。

#### (c) 非复制多请求流水线
- 每个 Transformer 层被分配给一个唯一的承载权重的 CT 集群（pipeline stage）；
- 多个请求以不同时间偏移沿层流水线注入：
  - 请求在多层间并行处理，预填充工作与解码工作互相重叠（图 4）；
  - 权重不复制（RRAM 只存一份）；每个请求保留独立 KV；
- 对解码阶段帮助最大：单请求生成单一 token 时计算量小，多请求交错填充停滞的计算资源并转化为实际利用。

#### (d) 状态感知资源重构（Power Management）
- 三类运行时状态区分：
  - 预训练权重（RRAM，非易失）
  - LoRA 参数（SRAM，易失但必须电源保持）
  - KV 缓存（SRAM/eDRAM，易失，跨请求保留）
- 集群进入低功耗状态时：保留持有 KV 或 LoRA 的内存供电，关闭 IPCN 路由器和闲置计算宏；
- 据此，功耗主要随“当前需求”而非“模型容量”或批大小线性增长，使功耗扩展呈亚线性特征。

## 6. 主要结论与发现

- **吞吐随模型规模/上下文增大而减小**；批量提高通过流水线填满实现性能 2.71×~3.91× 的提升（S 工作负载）；
- **批吞吐的增长为亚线性**，尤其对大模型；
- **UCIe 链路绝大部分时间仍低于 25% 占用率**，跨片数据传输不构成瓶颈；
- **LoRA 执行的开销主要来自 KV 内存资源冲突**（为留 LoRA 矩阵，KV 被推向 eDRAM）；批量高时，LoRA 吞吐可接近基础模式；工作负载多为 5% 差异（大多数长上下文/高并发时的性能系数 ~0.95-0.96）。
- KV 分配策略动态有效：短上下文全在 scratchpad，长上下文渐进 SRAM-DCIM；XL 时启用 eDRAM 层。
- TTFT 受输入长度影响最大（短到超长时 TTFT 提升 14×），批量大小提高影响很小（~20%）；LoRA 对 TTFT 影响 <5%。
- 平均功耗：IPCN+路由器为系统主功耗来源；
- 平均功耗不随上下文长度成比例放大的原因为总能耗的增加往往慢于执行时间的增加；
- 非复制多请求流水线设计使模型大小不同时能通过提高流水线占用率实现利用率的增益；深层模型（14B）利用率受批次限制较大，但空闲 CT 可通过电源门控关闭减少损耗；
- **与 Nvidia H100 对比**：在 Mistral-7B 长上下文（4096）INT8 配置下：批 1 时吞吐提升 2.38×，能效提升 27×；批 4 时吞吐提升 1.80×，能效提升 19.04×；
- 相对 Apple M4-Max 吞吐 12.26×/批1、10.71×/批4，能效 22× 和 16.1×；
- 能效远优于 Cerebras-2（Efficiency ratio 0.18 vs 27）等。

## 7. 优点

1. **统一架构覆盖大规模场景**；同时支持基础模式与 LoRA 模式、长短上下文、单/多请求并行，无需重新映射重型权重；
2. **权重零副本、无 RRAM 容量随批增长**，每请求带独立 KV，避免工业界“算力线性扩”的成本瓶颈；
3. **三级 KV 物理分配合纵（scratchpad + SRAM + eDRAM）策略**，高度可组合、不牺牲载荷局部性；
4. **将基础设施网络升级为计算引擎**：IPCN 内含 DMAC 能力，融合通信与运算，缩短关键路径，减少中间数据往返；
5. **分层、自适应的功耗门控策略**，将易失运行时状态与静态计算点分开管理，避免闲置片上逻辑持续漏电；
6. **软硬件协同扩展性**：提供编译器、API、接口和指令集，高层开发和应用调度简单自然；
7. 实验软硬件拟 7nm+Verilog+CACTI+周期精确模拟，具备工程可信度。

## 8. 不足与局限

1. **缺少组件级消融研究**；读者无法判断 IPCN、内存分层、流水线和电源门控各自的贡献率；
2. **实验未评估系统扩展性与模型超过 14B 或上下文超过 8K 时的行为**；技术验证极限未探测；
3. **缺少对精度量化（INT8）对推理质量影响的分析**，只测了硬件吞吐/能耗未提及任务质量下降或量化错误率；
4. **TTFT/ITL 仅报平均**，缺少尾部延迟与抖动参数，是调度场景评估的局限；
5. **模拟假设相对理想化**——未讨论请求中动态到达、超长 KV 满溢、跨片分配失效、路由拥堵等现实问题；
6. **未讨论 IP 内运行时状态的软件管理**细节（例如 KV 存储回收/stale 清理/OoO 处理策略），以及调度器对未来多层请求的流水线对齐方法；
7. **同类型硬件平台

7. **同类型硬件平台的比较公平性存疑**：对 CENT、CHIME 等学术平台的对标，未必在相同工艺节点（7nm）、相同模型/INT8 配置、相同输入长度条件下进行严格受控对比；不同 CIM 宏的精度、模拟器假设与功耗建模方式差异较大，可能放大或缩小能效倍数，读者难以判断性能差距中多少来自架构本质、多少来自建模口径不同。

## 9. 综合评价

CHIPSMORE 的核心学术贡献，在于把“计算在哪里做（计算分区）、数据在哪里存（KV 内存分级）、请求在哪里跑（跨层流水线）、电路何时通断（状态感知电源管理）”四个维度统一进一套可编译、可编程的芯片组架构中，从而把过去被割裂优化的多模式 LLM 推理问题（基础 vs. LoRA、短上下文 vs. 长上下文、单请求 vs. 多请求）转化为一套协调的资源调度问题。相较以往将 LoRA 支持、KV 扩展或高并发作为单一目标的加速器，这套系统在问题覆盖面、架构完整性以及软硬件协同深度上都达到了较高水准。

从工程可实现性看，论文采用 7nm 逻辑综合、CACTI 存储建模与周期精确指令级仿真相互印证，且给出了完整的指令集、存储映射和编译 API 设计，使得该架构不只是纸面概念。其“非复制多请求流水线”“互连内计算（IPCN 集成 DMAC）”“三态功耗重构”等思想，对未来面向长上下文、多租户 LLM 服务的 CIM 芯片设计具有明显借鉴价值。

但与此同时，论文在**实验纵深**上仍有欠缺：既没有组件级消融来剖析各机制贡献，也没有处理动态到达请求、KV 容量溢出与调度的时序行为；对 INT8 推理质量、尾部延迟等系统服务指标的讨论也基本缺失。因此，本文更多是一个**设计空间探索与架构论证**性质的工作，其定量结论可作为后续流片验证与系统软件完善的起点，而非面向量产部署的最终方案。总体上，该论文创新性较强、结构严谨、写作层次清晰，属于 CIM 与 LLM 加速交叉方向上一项值得关注的前沿工作。

## 10. 快速查阅要点

- **一句话概括**：CHIPSMORE 提出一种将 RRAM 存内计算、SRAM 数字存内计算、可编程互连路由计算以及 eDRAM 三级 KV 缓存统一编组的异构芯片组架构，以流水线无副本方式并发服务多请求、无缝切换基础/LoRA 模式，并以状态感知电源管理压低静态功耗。
- **关键机制记忆**：SMAC（静态 MVM 在 CIM 宏）／DMAC（动态 MVM 在互连路由器）；IPCN（可编程 2D mesh 计算网络）；三级 KV 池（Scratchpad → SRAM-DCIM → eDRAM）；8 层请求流水线。
- **最佳战绩**：Mistral-7B INT8 长上下文 Config 下较 H100 吞吐 2.38×（批 1）/1.80×（批 4），能效 27×/19.04×；较 M4-Max 吞吐 12.26×/10.71×。
- **主要局限**：无消融、无动态调度分析、无精度质量评估、无 >14B/>8K 极限压力测试、跨片比较口径可能不一致。
