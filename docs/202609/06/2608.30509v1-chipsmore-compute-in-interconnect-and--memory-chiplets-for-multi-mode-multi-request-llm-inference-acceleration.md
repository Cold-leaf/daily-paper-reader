## 摘要
大语言模型（LLM）推理在适应模式、上下文长度和请求并发性方面表现出显著差异，这对在计算内存（CIM）加速器上保持高利用率、内存效率和可扩展性能构成了挑战。本文提出CHIPSMORE，一种多模式多请求LLM推理加速器，它集成了互连计算和CIM，以支持在不同工作负载下的基础模式和低秩适应（LoRA）推理。CHIPSMORE采用由电阻式RAM模拟计算内存（RRAM-ACIM）和静态RAM数字计算内存（SRAM-DCIM）组成的异构处理单元，通过可编程的PE间计算网络（IPCN）互连。一种可组合的分层键值（KV）内存方案根据工作负载需求动态分配路由器暂存器、SRAM-DCIM和嵌入式DRAM（eDRAM）资源，实现对长上下文和批量推理的可扩展支持。此外，非复制多请求执行流水线利用请求级并行性而无需复制预训练权重，而状态感知的资源重配置机制选择性地保留运行时状态并对非活动资源进行电源门控，以提高能效。使用周期精确的软硬件协同仿真评估表明，CHIPSMORE在不同模型大小、上下文长度和批大小下有效维持高吞吐量，同时保持良好的功率扩展。与Nvidia H100相比，CHIPSMORE在Mistral-7B推理上实现了高达2.38倍的吞吐量和27倍的能效提升，同时消除了多请求服务的权重复制。

## Abstract
Large language model (LLM) inference exhibits substantial variability across adaptation modes, context lengths, and request concurrency, creating challenges for maintaining high utilization, memory efficiency, and scalable performance on compute-in-memory (CIM) accelerators. This paper presents CHIPSMORE, a multi-mode and multi-request LLM inference accelerator that integrates compute-in-interconnect and CIM to support both base-mode and low-rank adaptation (LoRA) inference under diverse workloads. CHIPSMORE employs heterogeneous processing elements consisting of resistive RAM analog compute-in-memory (RRAM-ACIM) and static RAM digital compute-in-memory (SRAM-DCIM) interconnected through a programmable Inter-PE computational network (IPCN). A composable hierarchical key-value (KV) memory scheme dynamically allocates router scratchpad, SRAM-DCIM, and embedded DRAM (eDRAM) resources according to workload requirements, enabling scalable support for long-context and batched inference. Furthermore, a non-replicated multi-request execution pipeline exploits request-level parallelism without duplicating pretrained weights, while a state-aware resource reconfiguration mechanism selectively retains runtime states and power-gates inactive resources to improve energy efficiency. Evaluation using cycle-accurate hardware-software co-simulation demonstrates that CHIPSMORE effectively sustains high throughput across varying model sizes, context lengths, and batch sizes while maintaining favorable power scaling. Compared with Nvidia H100, CHIPSMORE achieves up to $2.38\times$ higher throughput and $27\times$ higher energy efficiency on Mistral-7B inference while eliminating weight replication for multi-request serving.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **研究动机**：LLM 推理负载在三个维度上存在显著差异——**适应模式**（基础模型推理 vs. LoRA 低秩适应）、**上下文长度**（短/长/超长输入输出）以及**请求并发度**（batch size）。这些变化对 CIM（存内计算）加速器提出了不同的计算、存储和通信需求。
- **现有挑战**：
  - 单一固定架构难以同时高效支撑 prefill 与 decode 阶段，长上下文与短上下文对 KV cache 容量需求差异巨大，且 KV cache 随 batch size 和上下文长度线性增长。
  - 传统 CIM 加速器常为固定上下文、单一记忆角色或单请求执行设计；支持多请求吞吐扩展往往需要通过“权重复制”增加 RRAM 容量、芯粒数和泄漏功耗。
  - 静态预训练权重适合非易失 RRAM-ACIM，而动态数据/快速可重构参数（如 LoRA、中间激活和 KV cache）需要易失、可快速写入的 SRAM 或 DRAM，单一存储技术无法同时满足。
- **整体意义**：CHIPSMORE 旨在提出一种**统一的、多模式、多请求的 CIM 加速器架构**，联合优化计算组织、通信网络、KV 缓存分配和功耗管理，使系统在模型规模、上下文长度和并发度变化时仍能保持高吞吐、高能效和高资源利用率。
- 论文定位为解决“基础模式 + LoRA 适应 + 动态长上下文 + 无复制多请求”这一此前未被现有 CIM 加速器联合覆盖的设计空间。

## 2. 方法论：核心思想、关键技术细节

### 2.1 整体体系结构

- 采用 **chiplet 分层架构**：多个计算瓦片（Compute Tile, CT）通过 UCIe 互连；每个 CT 内用 2D Mesh 的 **IPCN（Inter-PE Computational Network）** 连接异构处理单元（PE）。
- PE 包含:
  - **RRAM-ACIM**（256×256 模拟存内计算宏）：存储并计算静态预训练权重（SMAC 操作）。
  - **SRAM-DCIM**（256×64 数字存内计算宏）：存储/计算 LoRA 矩阵；也可作为通用片上存储。
- 计算划分依据“操作数持久性”：
  - **静态权重相关计算（SMAC）** 在 CIM 宏内完成。
  - **动态运行时数据计算（DMAC）**，如注意力分数 Q·Kᵀ 的部分累加、激活处理等，在 IPCN 的计算路由器内**边传输边计算**（compute-in-interconnect）。

### 2.2 IPCN 可编程计算网络

- IPCN 由 **Network Program Memory（NPM）**、**Network Main Controller（NMC）** 和 **计算路由器（Router）** 组成。
- 采用专用 **30-bit IPCN ISA**，支持单播/广播和计算原语；NPM 采用双缓冲 Bank（B1/B2），由配置协处理器预加载指令，减少配置停顿。
- 路由器带 FIFO、控制器和多组“计算宏”（处理 partial sum、activation、DMAC），从而在通信路径上直接执行部分 AI 算子。

### 2.3 统一空间映射（Unified Spatial Mapping）

- 借鉴 LEAP 与 PRIMAL 方法：将 W_Q/W_K/W_V/W_O 等预训练矩阵按 CIM 阵列维度分块后，以“连续列矩形区域”方式固定映射到 RRAM-ACIM PE。
- LoRA 矩阵使用**完全相同的几何分块和空间位置**放入 SRAM-DCIM，保证本地累加 LoRA 贡献。
- 中间张量（Q、K、V、O）就近存放在对应路由/PE 的本地存储器中，减少数据移动；静态权重映射在所有模式下不改变，只有动态资源分配变化。

### 2.4 分层 KV 内存管理与 KV 容量公式

- KV 容量公式为：
  \[
  C_{KV} = \frac{B \cdot T \cdot L \cdot (2 N_{KV} d_{head})}{b_{KV}} \times 8 \text{ bytes}
  \]
  其中 B 为 batch size，T 为保留上下文长度，L 为注意力层数，N_KV 为 K/V 头数，d_head 为头维度，b_KV 为每元素位数；公式中因子2表示 key 和 value。
- 提出**三级可组合 KV 缓存层级**：
  1. **Router Scratchpad**——最高访问局部性、最低延迟；
  2. **SRAM-DCIM**——额外容量，基础模式下完全可用作 KV 存储，LoRA 模式下保留给适应参数；
  3. **eDRAM（2T0C 单元）**——大容量第三级，当 KV 需求超过 router scratchpad + SRAM-DCIM 时启用。
- 分配逻辑与工作模式挂钩：基础模式优先使用 scratchpad → SRAM-DCIM → eDRAM；LoRA 模式则 scratchpad → eDRAM（因为 SRAM-DCIM 被 LoRA 占用）。KV 超出单个 CT 时执行跨 chiplet 容量条带化。

### 2.5 非复制多请求执行流水线

- 每个 transformer 层静态绑定到一个“持有权重”的 CT 集群；多个请求在不同时间偏移进入流水线。
- 不同请求同时位于不同模型层中，因此**只存在一份 RRAM 预训练权重复制**，通过“层间流水并行”换取多请求吞吐。
- 每个请求保留独立的 KV cache 和运行时状态；decode 阶段可将请求级并行转化为硬件利用率。

### 2.6 状态感知的资源重配置和功耗管理

- 区分不同状态保留需求：RRAM 中预训练权重非易失；SRAM 中的 LoRA、分布式 buffer 中的 KV 属于易失状态，必须保电。
- 计算完成后，CT 进入低功耗状态：仅维持保存 LoRA/KV 的存储电源，IPCN 路由器和非活跃计算模块被 power-gate。
- 这样功耗主要随“活跃计算 + 需保留状态”扩展，而非总模型容量线性扩展。

## 6. 主要结论与发现

- CHIPSMORE 能够在基础模式和 LoRA 模式下，在不同模型大小、上下文长度和 batch size 中保持吞吐与能效优势；
- **相比 Nvidia H100**：
  - Mistral-7B 推理吞吐最高提升 **2.38 倍**（batch=1）；
  - 能效最高提升 **27 倍**（batch=1）；batch=4 时吞吐 1.80×、能效 19.04×；
  - 无需复制预训练权重即可实现多请求扩展。
- **Batch 扩展**：短负载中 batch 从 1 增至 4，Llama 3.2-1B 吞吐提升 3.91×、Mistral-7B 2.71×、Qwen3-14B 2.77×；由于流水线填充/排空、单层互斥及 IPCN/memory 争用等原因呈现**亚线性**。
- **上下文扩展**：XL 负载会激活 eDRAM 层级，引入额外访问延迟，造成吞吐下降；UCIe 即使在高并发下利用率仍未超过 25%，说明互连带宽不是瓶颈，CHIPSMORE 的数据局部化有效。
- **LoRA 开销**：LoRA 计算本身开销很小；主要性能下降来自 SRAM-DCIM 被 LoRA 参数占用导致 KV 分配层级改变（eDRAM 被更早启用）；batch=4 长上下文下 LoRA/base 性能因子恢复至约 0.95×。
- **功耗扩展**：状态感知电源门控使功耗扩展优于吞吐扩展；大模型 + 大 batch 总是增加功耗，但能效仍随 batch 提升，因为吞吐增加比功耗增加更快。
- **流水线利用率**：模型层数越浅（如 Llama 3.2-1B），batch 增大越容易填满流水线；深层模型（Mistral-7B 等）在 batch=4 下利用率仍有限，但空闲集群可被 power-gate 以节省功耗。

## 7. 优点

- **系统级协同设计**：将“适应模式选择、KV 缓存管理、多请求批处理、功耗管理”四个维度统一在一个架构框架中，突破了以往 CIM 加速器只优化一个维度的局限。
- **持久性感知的计算划分**：用 RRAM-ACIM 处理静态权重、IPCN DMAC 处理动态数据、SRAM-DCIM 兼顾 LoRA 和存储，符合数据生命周期特点，有较高设计洞察力。
- **可编程互连计算**：IPCN 不只是数据通路，还能在路由器内完成部分计算，减少中间激活搬运。
- **层次化、可组合 KV 缓存**：动态调整三层存储参与方式，很好地缓解长上下文和批处理带来的 KV 容量压力。
- **非复制多请求流水线**：避免了传统多请求实现中按复制因子线性增长 RRAM 面积和泄漏功耗的问题。
- **状态感知功耗优化**：区分易失/非易失状态的保电需求，实现细粒度 power gating，具备较强的工程实用性。
- **评估较细致**：不单报吞吐或能效，还分析 TTFT/ITL、UCIe 流量/利用率、内存分配、流水线利用率、面积组成，对硬件设计者有参考价值。

- **缺少真实负载与端到端质量评估**：论文只测吞吐/延迟/功耗，没有报告生成的文本质量（如困惑度、下游任务准确率），也没有验证动态长度/连续请求到达的稳定性。

- **固定模式**：上下文长度都是对称短/长/超长设定（输入=输出数量固定），与真实推理请求长短不一、稀疏到达的模式有差距。
- **仿真与配置限制**：所有结果基于 INT8 和周期精确模拟，缺少对更高精度/量化误差的讨论，也缺乏流片测试结果；模拟器的校准细节、功耗模型与实际物理偏差未讨论。

- **对比公平性存疑**：与 H100 等商用平台的对比横跨不同制程、存储层次、软件栈与测量环境，虽报告了显著优势，但未将对方功耗模型与批处理配置做同等约束；且对比平台本身仍在快速迭代，结论的时效性有限。
- **路由/互连计算与通用性**：IPCN 中实现的计算原语主要面向 transformer 的特定算子，对其他模型结构（如 MoE 路由、稀疏注意力、多模态编码器）的可编程性和扩展能力未做论述。

## 9. 未来研究方向（隐含与显式）

- 扩展 LoRA 与微调灵活性：探索不同 rank、W_Q/W_K/W_V/W_O 全投影覆盖、多 LoRA 并发调度，以及 LoRA 合并/切换策略。
- 引入动态工作负载：使用真实 LLM 推理 trace（如 ShareGPT、Azure LLM 推理数据集）驱动模拟器，验证请求长短混合、随机到达与优先级调度下系统的吞吐和 QoS。
- 端到端质量验证：结合量化误差分析，评估 INT8/混合精度下生成文本的困惑度与下游任务准确率。
- 硬件原型验证：在 FPGA 或先进工艺流片中实现关键 IPCN/CIM 模块，验证周期精确模拟器与实际电路的偏差，并测量真实能效。
- 系统软件协同：开发面向 IPCN 的编译器与运行时，自动完成“权重映射 → 流水线编排 → KV 层级分配 → 功耗门控”的端到端部署流程。
- 扩展至更大规模 chiplet 互连：研究 8/16 集群多芯粒拓扑下 UCIe 带宽、NoC 拥塞以及跨集群状态同步的扩展性。

## 10. 可复现性分析

- 论文提供了比较完整的架构级参数（7nm、1 GHz、宏容量、存储层次、互连拓扑），具备部分复现条件；
- 但缺少数值模型细节（如 RRAM 单元电阻/良率模型、CACTI 配置参数、功耗门控的电压/唤醒开销、UCIe 链路功耗系数）与公开源代码，第三方难以自行重建精确物理模型；
- 模拟器为自研指令级 + 周期精确混合模拟器，未公开接口与输入格式；
- 对比实验中的 H100 数据来自其他文献的测量（如 vLLM、公开基准），未提供统一的基准配置脚本。

## 11. 总体评价与建议

**总体评价**：CHIPSMORE 是一篇架构创新性强、问题定义清晰、实验维度较全面的 CIM 加速器设计论文。它抓住了当前 LLM 推理负载的关键变化（LoRA、长上下文、批量请求），将计算划分、存储层级与功耗管理统一起来，提出了一套可实际综合实现的多芯粒系统方案。论文在硬件设计思路上的贡献大于其在系统评测上的深度，属于“提出新架构 + 仿真验证”性质的正面工作。

**修改/改进建议**：

- 在实验部分增加 1–2 个基准消融实验：如去掉 router scratchpad 的 KV 容量、不使用层流水线而采用权重复制 baseline、禁用 IPCN 计算原语退化为纯路由，从而量化每项设计贡献；
- 将上下文设置改为真实分布（混合输入/输出长度），补充 TTFT/ITL 的尾延迟或 P99 分析；
- 补充 LoRA rank 变化、不同注入层和目标矩阵的影响；
- 对 INT8 带来的精度损失做简要量化，说明混合精度下模型质量的可接受性；
- 公开模拟器与配置参数，或在附录中给出更详细的功耗/面积分解表。

**一句话总结**：CHIPSMORE 以“不复制权重、动态适配、层次缓存、算网融合”为核心，首次将基础推理/LoRA 适应、多请求流水和 KV 分层管理纳入统一 CIM 加速器设计与仿真评估；尽管在真实负载和精度验证方面仍有不足，但它所展示的设计空间与工程方案对后续 LLM 推理加速器研究具有很好的参考价值与启发意义。
