## 摘要
大语言模型（LLM）推理在适应模式、上下文长度和请求并发性方面表现出显著差异，这对在存内计算（CIM）加速器上保持高利用率、内存效率和可扩展性能带来了挑战。本文提出CHIPSMORE，一种多模式多请求LLM推理加速器，它集成了互连内计算和CIM，以在不同工作负载下支持基础模式和低秩适应（LoRA）推理。CHIPSMORE采用由电阻式RAM模拟存内计算（RRAM-ACIM）和静态RAM数字存内计算（SRAM-DCIM）组成的异构处理元件，通过可编程的PE间计算网络（IPCN）互连。一种可组合的分层键值（KV）内存方案根据工作负载需求动态分配路由器暂存器、SRAM-DCIM和嵌入式DRAM（eDRAM）资源，从而支持长上下文和批量推理的可扩展性能。此外，非复制多请求执行流水线利用请求级并行性而无需复制预训练权重，而状态感知的资源重构机制选择性地保留运行时状态并对不活动资源进行功耗门控，以提高能效。使用周期精确的软硬件协同仿真进行的评估表明，CHIPSMORE在不同模型大小、上下文长度和批量大小下有效维持高吞吐量，同时保持良好的功耗扩展。与Nvidia H100相比，CHIPSMORE在Mistral-7B推理上实现了高达$2.38\times$的吞吐量提升和$27\times$的能效提升，同时消除了多请求服务的权重复制。

## Abstract
Large language model (LLM) inference exhibits substantial variability across adaptation modes, context lengths, and request concurrency, creating challenges for maintaining high utilization, memory efficiency, and scalable performance on compute-in-memory (CIM) accelerators. This paper presents CHIPSMORE, a multi-mode and multi-request LLM inference accelerator that integrates compute-in-interconnect and CIM to support both base-mode and low-rank adaptation (LoRA) inference under diverse workloads. CHIPSMORE employs heterogeneous processing elements consisting of resistive RAM analog compute-in-memory (RRAM-ACIM) and static RAM digital compute-in-memory (SRAM-DCIM) interconnected through a programmable Inter-PE computational network (IPCN). A composable hierarchical key-value (KV) memory scheme dynamically allocates router scratchpad, SRAM-DCIM, and embedded DRAM (eDRAM) resources according to workload requirements, enabling scalable support for long-context and batched inference. Furthermore, a non-replicated multi-request execution pipeline exploits request-level parallelism without duplicating pretrained weights, while a state-aware resource reconfiguration mechanism selectively retains runtime states and power-gates inactive resources to improve energy efficiency. Evaluation using cycle-accurate hardware-software co-simulation demonstrates that CHIPSMORE effectively sustains high throughput across varying model sizes, context lengths, and batch sizes while maintaining favorable power scaling. Compared with Nvidia H100, CHIPSMORE achieves up to $2.38\times$ higher throughput and $27\times$ higher energy efficiency on Mistral-7B inference while eliminating weight replication for multi-request serving.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：大语言模型（LLM）推理负载在**适应模式（base vs LoRA）、上下文长度、请求并发度**三个维度上差异巨大。现有基于存内计算（CIM）的加速器通常只针对单一或少数场景优化，导致在多样化真实工作负载下出现利用率低、KV 缓存扩展困难、多请求吞吐受限等问题。
- **关键矛盾**：
  - 预填充（prefill）与自回归解码（decode）的计算特征截然不同，单一硬件结构难以同时高效支持。
  - LoRA 推理要求硬件同时承载静态预训练权重与可快速重配置的低秩适配矩阵。
  - KV 缓存容量随上下文长度和批量大小线性增长，远超本地 SRAM 容量。
  - 常见多请求加速方案通过**复制模型权重**来提升吞吐，导致 RRAM 容量、芯粒数、面积与功耗按复制倍数膨胀。
- **整体含义**：该工作希望提出一种**统一、可扩展的 CIM 加速器架构**，在单一硬件平台上协同优化适应模式、KV 内存扩展和请求级并行，消除权重复制开销，兼顾吞吐量与能效。

### 2. 方法论（核心思想、技术细节与流程）

- **核心思想：持久性感知的计算划分（Persistence-Aware Compute Partitioning）**
  - 将与静态预训练权重相关的运算（SMAC）放在 RRAM-ACIM 中执行。
  - 将与运行时动态数据相关的计算（DMAC，如注意力分数 Q·Kᵀ）放在互连网络 IPCN 的路由器中执行（compute-in-interconnect）。
  - 优势：保留 CIM 权重固定的优势，同时减少中间激活的搬运开销。

- **硬件架构层次**
  - **PE（处理单元）**：每个 PE 同时包含 RRAM-ACIM（存预训练权重，256×256 阵列）与 SRAM-DCIM（存 LoRA 矩阵或充当 KV 存储，256×64 阵列）。
  - **IPCN（PE 间计算网络）**：2D mesh 结构，包含 NPM（网络程序存储器）、NMC（主控制器）、CC（配置协处理器）与计算路由器。路由器支持 30 位专用 ISA，可同时做路由、FIFO 暂存、部分和累加、激活函数与 DMAC。
  - **eDRAM（第三级 KV 存储）**：采用 2T0C 单元，用于超长上下文时超出 SRAM 容量的 KV 数据。
  - **跨芯粒（Chiplet）互联**：通过 UCIe 接口连接多个 compute tile（CT），构成统一可扩展加速器。

- **统一空间映射（Unified Spatial Mapping）**：沿用了 LEAP/PRIMAL 的空间映射方法，将 WQ/WK/WV/WO 与对应 LoRA 矩阵按相同几何分块边界放到同一 PE 组中，保证 LoRA 修正项可局部累加到 base 输出内。

- **分层 KV 内存分配方案**
  - KV 缓存按优先级从高到低分配：**路由器暂存器（scratchpad）→ SRAM-DCIM → eDRAM**。
  - Base 模式下 SRAM-DCIM 可全部用于 KV 缓存；LoRA 模式下 SRAM-DCIM 优先保留给 LoRA 矩阵，KV 只能依赖暂存器和 eDRAM。
  - 支持跨 CT 的容量条带化（capacity striping），并给出 KV 容量公式：
    C_KV = BT·L·(2·N_KV·d_head)·b_KV / 8 bytes。

- **非复制多请求流水线（Non-Replicated Multi-Request Pipeline）**
  - 将每个 Transformer 层固定映射到唯一的权重承载型 CT 集群上。
  - 多个请求按时间错位注入，不同请求可同时位于模型的不同层上执行，形成**跨层流水线**。
  - 所有请求共享同一份 RRAM 权重，无需复制模型参数。

- **状态感知的资源重构与功耗管理**
  - 按保留状态类别区分：RRAM 权重不依赖供电保持；SRAM-DCIM 中 LoRA 参数和 KV 数据需保电。
  - 层执行结束后，若集群仍持有 KV/LoRA，则仅保留所需存储阵列供电，对 IPCN 路由器和无关计算模块实施功耗门控。
  - 由此实现功耗随“激活计算量+保留状态量”缩放，而非随模型总容量线性增长。

- **工作模式**：支持 Base 和 LoRA（rank-8，应用于 Q、V 投影）两种模式，上下文长度分为 S/L/XL 三档，批量大小为 1/2/4。

### 6. 主要结论与发现

- **主要结论**：
  - CHIPSMORE 在不同模型（1B/7B/14B）、不同上下文长度（S/L/XL）、不同批量（1/2/4）和不同模式（Base/LoRA）下均能保持较高吞吐和可扩展的 KV 存储能力，可动态复用内存层级。
  - 多请求吞吐提升不需要复制模型权重；基于层流水线的交错调度将请求级并行转化为硬件利用率，但提升为**亚线性**（1B 模型 batch 1→4 提升 3.91×，7B 为 2.71×，14B 为 2.77×）。
  - LoRA 带来的吞吐开销主要不是来自低秩矩阵计算量本身，而是来自 KV 内存层次的变化（SRAM-DCIM 被 LoRA 占用后，KV 溢出到 eDRAM），长上下文 + batch=1 时性能可降到 base 模式的 ~71%；大 batch 下可回升至 ~95%。
  - IPCN/路由器子系统是功耗最大组成部分；平均功耗增长幅度低于吞吐增长，能效较高。eDRAM 虽然扩大了容量，也会引入访问延迟开销，使平均功率不随上下文线性上升。
  - UCIe 互连利用率最高不超过 25%，不是系统瓶颈，说明 intra-CT 数据局部性组织有效。
  - 相对 Nvidia H100，CHIPSMORE 在 Mistral-7B 上吞吐最高提升 2.38×，能效最高提升 27×（batch=1 时 36.24 vs 1.34 tokens/J），同时杜绝了多请求场景下的权重复制。

### 7. 优点与亮点

- **细粒度、面向持久性的计算划分**：静态权重上 CIM、动态数据在路由器内计算，比单一 CIM 更贴合 LLM 推理中“权重固定、激活动态变化”的特点。
- **统一的多模式映射**：Base 与 LoRA 共用同一空间几何分块，切换模式不需要重新映射 PE，只调整内存分配策略。
- **三层次 KV 内存动态编排**：scratchpad→SRAM-DCIM→eDRAM，既有软件灵活性又保留数据局部性，是解决长上下文和多请求 KV 扩展难题的较完整方案。
- **消除权重复制的多请求流水线**：设计思路直击目前在 multi-request CIM 系统中面积/功耗随 batch 复制增长的关键痛点。
- **状态感知功耗管理**：按保留状态的类型与位置做功耗门控，模式粒度细，有助于解释为何平均功耗增长可以显著低于模型规模扩张速度。
- **验证较充分**：RTL 验证、逻辑综合、CACTI、周期精确模拟器多层次覆盖；与 H100/SoC/CIM 平台都有横向对比。

### 8. 不足与局限

- **实验覆盖面有待扩展**：batch 最大为 4，与真实系统中几十到上百并发相距较远；上下文最高为 8K/8K，未覆盖当前主流的长上下文（32K+）场景。
- **缺少质量/精度指标**：所有实验只统计吞吐与延迟，没有用真实数据集评估生成质量（如困惑度、MMLU 等），没有报告量化（INT8）后的精度损失，无法判断实际部署可用性。
- **LoRA 评估范围不全**：仅测 rank-8 且只作用于 Q、V 矩阵，未能覆盖不同秩、不同目标模块以及同时多任务切换时的开销。
- **未做独立消融分析**：各设计模块（IPCN 计算、KV 三级分配、状态感知门控、层流水线）对整体增益的独立贡献无法从现有数据中单独剥离。
- **对比公平性受限**：与 GPU/Cerebras 等平台的对比中，CHIPSMORE 是基于模拟器/综合结果的数据，而基线（如 H100）是实测，功耗和吞吐的统计口径不一；且对比工作没有覆盖实际各平台软硬件栈差异（例如分页 KV 管理、调度开销）。
- **未讨论端到端供电/热/封装约束**：未见与芯粒级功耗密度、UCIe 封装的能耗/面积细节、跨芯粒一致性开销等硬件工程化问题的深入分析。
- **场景特殊性**：评估工作负载是合成均匀批量请求，未包含多轮对话、混合长短请求流、任务切换和 LoRA 适配器热插拔等真实服务动态行为。
