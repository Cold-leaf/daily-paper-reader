## 摘要
LLM推理已成为一项必不可少的服务，但它对内存带宽、计算密度和通信效率提出了前所未有的要求。虽然IMC是解决内存墙问题的一种有前景的方案，但LLM的异构数据动态性需要互补资源来处理运行时产生的中间数据。此外，LLM中海量的参数需要扩展架构，其中片上数据移动通常是主要的性能瓶颈。本文提出了一个软硬件协同设计框架，将分布式计算、内存和通信统一到一个无缝的处理-通信结构中。在硬件方面，我们提出了一种名为LEAP的可扩展架构，它集成了IMC PE、NMC PE和INC，使得每个硬件层都能执行专门的任务：IMC负责静态权重，NMC负责动态数据，INC负责部分结果归约。在软件方面，我们引入了一个针对LLM服务中的关键指标（包括吞吐量和延迟）进行优化的分区、映射和调度框架。为了解决prefill和decode阶段不同的计算强度，我们提出了一种prefill-decode分离方法，该方法通过动态重新配置PE组织来最大化资源利用率。与商业GPU平台相比，所提出的架构的吞吐量提高了$\geq{}1.52$倍，能效提高了$24.91$倍。

## Abstract
LLM inference has become an essential service, yet it imposes unprecedented demands on memory bandwidth, computational density, and communication efficiency. While IMC is a promising solution to the memory wall issue, the heterogeneous data dynamicity of LLM requires complementary resources to handle intermediate data generated during run-time. Furthermore, the massive number of parameters in LLM necessitates scale-up architectures where on-chip data movement is often the primary performance bottleneck. This article presents a hardware-software co-design framework that unifies distributed compute, memory, and communication into a seamless processing-communication fabric. On the hardware side, we propose a scalable architecture, named LEAP, that integrates IMC PE, NMC PE, and INC. This allows each hardware layer to execute specialized tasks: IMC for static weights, NMC for dynamic data, and INC for partial result reduction. On the software side, we introduce a partitioning, mapping, and scheduling framework optimized for key metrics in LLM serving, including throughput and latency. To address the distinct computational intensities of the prefill and decode phases, we present a prefill-decode disaggregation approach that dynamically reconfigures PE organizations to maximize resource utilization. Compared to commercial GPU platforms, the proposed architecture provides a throughput and an energy efficiency improvement of $\geq{}1.52\times$ and $24.91\times$, respectively.

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将三类计算资源“专用化”，以匹配 LLM 推理中的不同矩阵操作类型：
  - **IMC PE**：存储静态权重，执行“动态矩阵 × 静态矩阵”乘法（**DSMM**）；
  - **NMC（近存计算）资源（路由器内 scratchpad + MAC）**：存储动态数据，执行“动态矩阵 × 动态矩阵”乘法（**DDMM**），如 QKᵀ 和注意力分数 × V；
  - **INC（路由器内计算单元，IRCU）**：在数据路由过程中完成部分和归约（Reduce/AllReduce 等）。
- **硬件模板**：由宏单元（macro）阵列和 2D Mesh NoC 构成；每个宏包含 IMC PE、带有 scratchpad 和 IRCU 的路由器。支持两种硬件配置：
  - **LEAP-A（Aggregated）**：所有宏同构，prefill 与 decode 共享资源；
  - **LEAP-D（Disaggregated）**：prefill 区宏保留 IMC PE；decode 区宏去掉 IMC PE，扩充 scratchpad 容量，以提供更高内存带宽与并行度。
- **软件框架**：
  1. **分区**：按 IMC crossbar 尺寸与 IRCU/scratchpad 容量，将权重矩阵与动态 Q/K/V/O 矩阵沿行/列维度细粒度切分；
  2. **映射**：
     - 层内映射采用启发式规则（同源子矩阵连续、尽量矩形、行/列主序展开）；Q/K/V 按列主序跨 tile 映射，O 按行主序跨 tile 映射；
     - 层间映射采用蛇形（serpentine）拓扑，以支持解码阶段 token 逐层回传，且每个 decoder 的 attention 与 FFN 的 IMC 容量近似相等，便于规则化布局；
     - KV cache 采用循环存储（cyclic storage）策略，确保内存利用率均衡。
  3. **数据流模式**：定义了 Broadcast、Reduce、ReduceScatter、AllGather、AllReduce 等确定性数据流模式，支持编译期确定路由，降低运行时开销。
- **Prefill/Decode 分离**：
  - 论文对比了聚合模式（LEAP-A）与分离模式（LEAP-D）的数据流。LEAP-D 将 KV 缓存从 prefill 区传输到 decode 区，但设计上通过计算–通信重叠消除该传输的关键路径开销。
- **序列批处理调度**：讨论了批大小为 2 的轻量级调度策略（边缘场景），分析两个请求在 prefill/decode 并发时争夺 IMC 权重访问造成干扰，并提出相应协调方法。

## 6. 论文的主要结论与发现

- LEAP 架构相比 A100/H100 优势显著：以 Llama 3-8B 为例，LEAP-A 比 A100 吞吐高 2.55×、能效高 71.94×；LEAP-D 比 H100 吞吐高 1.52×、能效高 24.91×。
- 通过 LEAP-D 分离 prefill/decode，可显著缩短 decode 与 prefill 的吞吐差距，核心原因是扩大了 decode 区的并行存储带宽并消除了 pipeline 瓶颈。
- 模型规模扩大时，吞吐量的退化小于模型参数规模的线性增长：因为关键路径只随部分维度（如 se·sl 或 sh·sl）扩展，呈现次线性退化。
- 关键路径主要受数据移动和 IRCU 内 DDMM 运算限制，而非 IMC 操作；采用 64-bit 包宽与 16 路 IRCU 并行接近性能—资源最优折中（roofline 分析）。
- 批处理可以明显改善 TTFT，但会增加 TPOT（因为两个请求竞争 IMC 访问权），因此 batching 与 non-batching 应作为两种互补模式：TTFT 敏感应用适合前者，TPOT 敏感应用适合后者。
- 能量效率大幅提升的根本原因在于全分布式计算–存储组织与确定性数据流极大减少了数据移动。

## 7. 优点：方法或实验设计上的亮点

- **硬件架构创新性强**：将 IMC、NMC、INC 统一到同一 NoC 宏单元中，按矩阵数据类型分工，针对性极强——IMC 负责静态权重、NMC 负责动态数据、INC 负责**在传输中归约**，避免大量部分和在 PEs 与路由器间反复搬移。
- **软硬件协同完整**：从分区、映射到数据流定义了确定性模式，编译期决定路由，运行时开销小；提出的启发式映射能有效降低映射空间复杂度。
- **Prefill/Decode 分离方案贴合硬件能力**：不是静态硬件完全隔离，而是利用同构宏的可重构性和 KV 转移与计算重叠技术，实现无关键路径开销的分离模式。
- **关键路径分析与 roofline 分析提供了定量设计指导**：能清晰指出瓶颈所在（数据移动与 DDMM），而非笼统给出性能数字。
- **评估维度丰富**：包括吞吐、能效、面积、功耗、关键路径拆解、模型扩展性、批处理影响等多层次评估，相比仅报单点性能的工作更完备。
- **扩展性好**：2D mesh 按宏复制扩展，面积比例恒定；3 种模型规模验证了次线性退化特征。
